# Agent 可靠性核查

| 场景 | 问题与修复 | 可验证行为 |
| --- | --- | --- |
| 模型请求响应丢失 | 模型入口未使用持久请求登记。现在可用 Idempotency-Key 领取规划请求，重复提交重用 Run。 | 同一键和相同请求只调用一次提供方；同一键和不同请求返回 409。 |
| 部分提交后 Worker 接管 | 查询返回任意非空回执就会被认为已确认。现在检查任务、步骤、原提案载荷，以及持久回执摘要。 | 回执不同保留 UNKNOWN，记录 RECEIPT_MISMATCH。 |
| 页面操作与状态 | 持久任务缺少取消入口，终态仍轮询，暂时读取失败时覆盖整页。 | 任务可确认取消，终态停止轮询，暂时错误保留已加载证据。 |
| 持久队列观测 | 系统页的 Worker 数据主要来自进程内运行器。 | 独立显示持久队列的排队、有效租约及待接管任务。 |
| 执行保证说明 | 三个相同的 NOT_IMPLEMENTED 标签无法表达已有能力。 | 分开说明受控 HTTP、第三方效果、跨库对账与 GPU/KV 指标。 |

模型请求已登记但模型调用结果未确认时，重复提交不会自动再次调用提供方。如果任务已经落入队列，查询原请求可以返回该 Run。浏览器在重试间保存请求键和提交摘要，实际输入仍来自表单。

受控 HTTP 的效果与回执在共享 SQLite 事务内提交。第三方接口的确认依赖其实际契约，独立数据库各自提交并通过可核验回执对账。GPU/KV 指标尚未采集。局部修复和 Token 收益的证据边界见 [算法评测](EVALUATION.md)。
