# 新颖性核对

核对日：2026-11-06。性能数字出现之前写完。真实 Git 历史和 Irrelevant 组本身不构成新 benchmark。

## SWE-bench Verified

来源是 princeton-nlp/SWE-bench 的 Verified 子集，500 个经过核验的任务。它有真实 issue、`base_commit`、参考修复和测试，并用 Docker 评分。

该评测没有做这项测量：Agent 执行过程中注入另一个真实历史提交，再比较相关、无关和不确定更新下的证据刷新。标准任务假定仓库在执行期间不变。

## SWE-Shift

论文是 SWE-Shift: Evaluating Coding Agents in Evolving Workspaces，arXiv:2610.32196。它从同一保存的历史和工作区分叉 Clean 与 Shifted。Shifted 接收的是任务相关、并且变更后仍可完成的更新。120 个场景、12 类变化、9 个干预位置。评分包括完成当前任务、保留仍然有效的工作，以及状态和证据检查。公开摘要还写到：不影响任务的变化被排除。

因此它已经测量了共享 checkpoint、相关变化、工作保留和证据新鲜度。本协议不能把这些再写成新发现。

该论文没有做这项测量：把同一仓库里时间上更晚、而且被标成无关或不确定的真实提交，配成负对照，观察 Agent 会不会放弃仍然有效的工作。它也没有在 DSH 0.2.2-rc.1 上把文件版本哈希和 Session 前缀绑在一起审计。

如果后面的实验只是重复“相关更新之后成功率下降”，就停止创新论文，保留工程记录。

## 还允许问的问题

同一执行前缀上，真实历史更新的相关性、证据失效和必需刷新是不是三种不同的错误。这个问题要在六项准入都通过的样本上问。样本不够就停在数据可行性报告。
