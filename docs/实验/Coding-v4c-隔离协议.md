# Coding v4c 严格隔离协议

写于 v4 提示审计之后。v4 的轨迹、`confirm/summary.json` 和其中的通过数不改，不重新标成严格隐藏评测。

v4 的九个任务都把隐藏测试打到 base 上之后的 pytest 失败行放进了模型输入。其中五个任务的失败行带有断言期望，九个都带有异常或失败计数。零个任务看到了隐藏测试 diff 本身。这是协议写明允许的失败行，所以那一批的名称是固定失败反馈下的修复，不是严格隐藏评测。

## 这一批改什么

确认任务仍是 `frozen-tasks.json` 里的六个，不换任务，不用来改 v4 的提示或预算。开发集不重跑。

模型输入只有修复提交的第一段说明。不调用 `visible_symptom`。不放入隐藏测试源码、断言期望、异常文本或失败计数。若提交说明里的引号字符串已经出现在隐藏测试补丁中，这一段预期说明撤下，并在轨迹里记 `expected_withheld`。

隐藏测试只在容器评分端使用。工作区里原来就有的测试仍可由 `run_public_tests` 运行。预算与 v4 相同：24 轮、40 次工具、420 秒，温度 0。

结果目录是 `results/runtime/correctness/v4c-isolated/`。不与 v4 的 4/6 相加。
