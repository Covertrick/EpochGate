# EpochGate 配置选择实证研究计划

日期：2026-11-21。状态：**Conditional GO，待冻结先导协议**。

拟题：*Beyond Authorization Compliance: The Decision Value of Business Semantics and Successor Obligations in Agent Runtime Selection*。

**先批准六格验收和 12–16 簇先导。** 正式确认和投稿取决于同一批目标记录上，业务语义与后继义务能否在终态加授权合规的基础上，提供可复核且有工程意义的配置决策增量。

## 1. 研究问题和范围

| 问题 | 可检验的回答 |
| --- | --- |
| RQ1 · 增量判定 | 对已经通过终态和目标侧授权判定的运行，提交时业务语义和必需后继义务各自发现了什么？ |
| RQ2 · 配置推荐 | 增加这些证据后，哪些部署约束下的合格集合或成本最优推荐集合发生变化？由哪条目标事件驱动？ |
| RQ3 · 通知交互 | 对同一配置，通知交付是否影响目标效果？它是否进一步改变 Claim 与 Admission 的差异和配置推荐？ |
| 外部效度 | 在留出的 Release / Workflow 任务族中应用已冻结的规则，确定结论可迁移的范围。 |

主结论的单位是**受测执行配置**。Direct、Admission 和 Claim 的检查时点、持久化及回执能力可能同时变化。若后续要归因到其中一个组件，需要另做单组件对照。Outbox、故障恢复、线上模型质量和第二执行边界留作独立问题。主批使用确定性冻结动作和 SQLite 目标，结论限于约定的任务、故障和执行能力。

## 3. 五个判定维度与推荐规则

### 3.1 逐格判定

| 维度 | 从什么证据重算 | 判定 |
| --- | --- | --- |
| T · 终态 | 目标最终状态与预先定义的业务目标 | `PASS / FAIL / UNKNOWN` |
| A · 授权 | 目标提交时的主体、动作、资源、范围与权威策略版本 | 对实际效果判 `PASS / FAIL / UNKNOWN`。内部 token 仅用于解释配置行为。 |
| E · 证据 | 独立目标账本、已接受的效果与可核查的拒绝证据 | `CONFIRMED_APPLIED / CONFIRMED_NOT_APPLIED / UNRESOLVED / UNOBSERVABLE`。原生回执另表。 |
| S · 语义 | 目标接受效果时的业务状态及实际载荷 | `PASS / FAIL / UNKNOWN`。权限仍有效而库存不足时，可以 A 通过、S 失败。 |
| N · 后继 | 预先声明的义务、触发条件、效果谱系与关闭证据 | `REQUIRED_SATISFIED / REQUIRED_MISSED / NOT_APPLICABLE / VALIDLY_CANCELLED / UNKNOWN`。 |

同一个效果可以同时触发多个维度，分别计数并保留共同的效果标识。按目标记录确认没有任何效果时，A 和 S 可按全称约束通过，但另报「无效果」；未观测到记录且无法证明目标没有提交时，保留 UNKNOWN。S1 通过但 S2 失败与 S2 未知分别计数。对多效果任务，有确定违规时报告失败，同时保留任何其他未知项。

### 3.2 在同一批运行上计算评价阶梯

| 层级 | 必须通过的判定 | 用途 |
| --- | --- | --- |
| S0 | T | 终态基线 |
| S1 | T、A | 已考虑目标侧授权违规的强基线 |
| S2-Sem | T、A、S | 定位业务语义的增量 |
| S2-Succ | T、A、N | 定位后继义务的增量 |
| S2 | T、A、S、N | 完整历史评价 |

E 用于确认相应维度有可用证据。证据不足产生 UNKNOWN。五层使用同一轨迹、样本权重、终态门槛及成本定义。主比较是 **S1 → S2**，S0 → S1 作已知现象的参照。两个诊断层各自与 S1 和 S2 对比，定位某项约束单独改变选择，还是联合筛选才改变选择；此比较描述规则作用。

### 3.3 合格、成本和未知处理

在每个冻结的通知条件和部署情境下，先用终态要求形成 F0，加入授权约束得到 F1，再加入语义与后继义务约束得到 F2。每层在合格配置中计算成本 Pareto 非支配集合。成本向量记录端到端时间、实际工具调用、实际重试和运行时内检查或持久化成本。为每一项固定计量单位、边界和汇总方式。例如端到端时间从业务运行启动到终态封存，排除实验准备、离线审计和人工暂停。运行时成本如已包含在端到端时间中，分量可另报，在加权分析中避免重复计价。

`decision_policy.json` 在先导前填写以下参数及其依据。确认前可根据先导暴露的可行性问题修订，修订后使用新样本。

| 参数 | 冻结要求 |
| --- | --- |
| `tau_terminal` | 最低终态完成要求，给出部署需求来源或明确标为假想使用情境。 |
| `max_authority_violation`、`max_semantic_violation`、`max_successor_miss` | 分别规定容忍度、统计单位与分母。零容忍表示已观测的违规会使该批配置不合格，不能解释成总体风险为零。后继分母仅统计适用义务。 |
| `max_unknown` | 按维度冻结未知上限。未知可能改变合格性或推荐集合时，判证据不足。 |
| `delta_terminal`、`delta_cost` | 按部署 SLA、工程最小有用差异和计量分辨率定义，成本按分量给阈值。无依据的维度只报告差异与区间，省略等效主张。 |
| `weights` | 冻结各任务与故障层的权重、主成本向量及敏感性配置。没有真实标量权重时，保留 Pareto 集合。 |
| `stability` | 预设 10,000 次簇重抽样、固定种子、集合复现率暂定 90%。同时报告各配置入选频率与无解、缺证频率。90% 是操作性稳定标准，不能替代统计证据。 |

对有 UNKNOWN 的候选，至少计算与已知证据相容的乐观和保守结果。两者若改变资格或推荐，输出证据不足，补充说明需要哪些证据。完全已知且合格集合为空时，输出无可推荐配置。

| 推荐变化 | 判定条件，对 S1 → S2 为主 |
| --- | --- |
| 打破平局 | 原有多个实际等价候选，新规则缩小集合。成本向量之间的取舍另记为 Pareto 集合缩小，避免把非支配当成等价。 |
| 严格翻转 | 原规则稳定唯一推荐 A，新规则稳定唯一推荐 B，并能解释两者的成本、资格和违规差异。 |
| 仅诊断改变 | 推荐集合相同，新证据指出此前未识别的违规或义务缺口。 |
| 无变化 | 推荐和诊断均无实质变化，或观察到集合完全相同并明确可支持的范围。 |
| 无可推荐 | 已知证据足以判定没有合格配置。 |
| 证据不足 | 缺证、边界不确定或推荐集合不稳定。 |

另保留集合由单一变多或由部分候选换为部分候选的原始集合差和原因，避免强行归类。统一输出每层的合格集合、推荐集合、驱动事件、敏感性和缺证清单。

## 4. G1 · 六格执行验收

### 4.1 复用路径与隔离

新实验单独建目录，建议 `experiments/configuration_selection/` 保存协议、运行入口、审计入口和评分器。结果写到 `results/experiments/configuration-selection/<batch-id>/`。优先复用 `fault_replay` 的冻结提案和路径入口、`effect_history` 的独立目标证据与重算方式。旧 E4 脚本的 Full 专属通知注入只用于解释历史设计。

| 同簇配置 | 通知分配 D1 · 送达 | 通知分配 D0 · 未送达 |
| --- | --- | --- |
| Direct | 同一通知抵达入口，保留原执行路径 | 同通知生成后在传输层丢弃 |
| Admission | 同一通知抵达入口，走原准入检查 | 同通知生成后在传输层丢弃 |
| Claim | 同一通知抵达入口，走原 Claim 提交路径 | 同通知生成后在传输层丢弃 |

六格用同一个提案摘要、初始快照、权威策略、业务变化、检查点和预算。每格克隆初始快照，使用独立 `run_id`，不同运行有独立效果命名空间，同一运行中原动作与同一逻辑效果的重试保持稳定标识。冻结六格执行顺序的随机种子。检查点用屏障和逻辑序号。先把三条真实路径的检查点、可读状态、后继触发和涵盖成本的边界画成调用表。

### 4.2 每格最低事件证据

1. `BUSINESS_STATE_COMMITTED` 和独立的 `AUTHORITY_POLICY_CHANGED`。只有真实权限变化才产生后者。业务通知引起内部尝试代际变化时另记内部状态。
2. `NOTIFICATION_EMITTED`、`TRANSPORT_DELIVERED / TRANSPORT_DROPPED`、`CONTROL_PLANE_RECEIVED`、实际应用或忽略的结果。使用同一事件 ID 贯穿全部记录。
3. `PRECOMMIT_CHECK`、`SINK_DECISION`、`EFFECT_COMMITTED / EFFECT_REJECTED`。记录实际字节或摘要、效果标识、权威版本、业务版本和目标端提交顺序。目标确实没有提交需要可核查的证据。
4. `SUCCESSOR_OBLIGATION_RESOLVED`、`TERMINAL_STATE`。后继是否执行由该配置的真实处理路径决定。保留父尝试、义务标识和实际操作计数。

每格保存 `input.json`、`events.jsonl`、目标快照或账本、原生回执、错误及判定来源。先封存、再清理资源。运行入口拒绝覆盖旧批次。审计入口以只读方式验哈希、查缺失与重复，并从目标记录独立重算。

主实验如果能限制 Planner 在屏障后读取权威业务状态，就审计每次绕过通知的读取。无法隔离时，冻结所有臂同样的读取权限并记录实际读取，研究结论表述为「在该读取策略下，通知交付分配的影响」。按 D1/D0 的预先分配做主分析。实际接收和应用是中间事件。异常投递保留原分组并报告；先导出现系统性的交付错误时暂停修复。

**G1 验收**：先跑库存语义失效六格，再跑无变化和真实授权撤销控制。检查同簇输入摘要一致、D1/D0 确实分离、共同观察器公平、后继由实际路径触发、未知能保留、不会覆写产物。人工对照少量已知正反例核验评分程序。交付 `six_cell_acceptance_report.md` 及完整证据包。

## 5. G2–G4 · 批次、场景与分析

| 批次 | 预算 | 数据范围和退出条件 |
| --- | --- | --- |
| G2 先导 | 12–16 簇，72–96 格 | Inventory / Order Fulfillment。验证证据链、估计不一致率、寻找 S1 → S2 的决策增量。发现增量且能指出驱动事件才扩批。只出现 S0 → S1 时停止原主张。 |
| G3 确认 | 起始预算 36–48 新簇，216–288 格 | 新库存或履约实例。按先导不一致率、最小有用配对差和预算核定所需样本。预算不足时收窄问题或接受不确定结果。 |
| G4 留出 | 12–16 新簇，72–96 格 | Release / Workflow。相同 SQLite 执行接口，任务语义独立于先导。报告是否复现推荐变化及其原因。文件发布另算执行边界验证。 |

预案分配 12 个模板，库存履约与发布工作流各 6 个。先导与确认可共享库存任务族，使用不同实例。记录它们共享的模板层级。发布族在确认规则冻结前保留，报告模板内相关性和模板级敏感性。重复执行或更换随机种子不能自动产生独立簇。

| 场景 | 必须控制的条件 | 判定用途 |
| --- | --- | --- |
| 库存语义失效 | 库存 8 → 2，旧动作需 3；业务权限仍有效 | 检查 A 通过时 S 是否带来增量 |
| 条件仍成立 | 库存 8 → 6，旧动作仍需 3 | 测合法动作被拒及后续实际工作 |
| 后继义务 | 预先冻结何时必须执行、允许转移或取消 | 检查终态达成时义务是否仍遗漏 |
| 真正授权撤销 | 业务谓词可继续成立，执行权限失效 | 证明 S1 可发现的违规类型 |
| 无变化 | 世界与权限维持，通知计划写明 | 检查观察与调度过程是否引入误伤 |

场景和故障是分层变量，主表按任务族与通知条件报告。跨层汇总仅使用冻结权重。测试矩阵中的发生频率适用于这些构造场景。

### 统计方案

- 固定 **Claim 对 Admission** 为主配置比较，Direct 作参照。确认前指定单个主统计终点及分析条件。可采用已证实的 `S1 PASS / S2 FAIL` 在全部分配簇中的配对差，同时报告 S1 通过子集的分子与分母。推荐集合变化另用同一批数据作决策分析。
- 保留每个簇的六格，计算通知交互 `[(Claim,D1) − (Claim,D0)] − [(Admission,D1) − (Admission,D0)]`。二元两臂比较报告不一致对和配对差区间，必要时用精确 McNemar。交互和成本以簇为单位构造区间，模板共享时做模板层重抽样或分层敏感性分析。只有随机分配及交换条件确实成立时使用随机化推断。
- 使用先导估计配对不一致率及其不确定性，并结合最小有用差异规划确认批。二元主比较可用精确检验规划，交互用保留六格相关性的模拟。默认双侧 α=0.05 与目标功效 80%，列明假设和预算限制。次要推断按预先定义的假设族做 Holm 校正。
- 近似等效主张需要预先定义的差异界限及与配对设计相容的等效分析。达到显著或未达到显著与部署推荐稳定性分别报告。
- 主表对每个条件报 T、A、E、S、N、S1 通过但 S2 失败、S2 未知和成本。推荐表输出 S0、S1、两个诊断层与 S2 的候选集合和稳定性。代表性的每一项变化附可定位的目标事件。

### 停止与收窄条件

| 结果 | 决定 |
| --- | --- |
| S1 与 S2 的推荐一致，仅 S0 → S1 有变化 | 停止原主张，保留复现及授权诊断。 |
| S2 多检出违规，推荐不变 | 保留诊断结果。只有能展示实际监控或排障决策受影响时再评估长文。 |
| S1 → S2 在确认批稳定改变推荐，并且事件可审计 | 继续留出验证和写作。优先报告严格翻转或有实际成本意义的集合缩小。 |
| 先导有效，确认不支持 | 报告未复现，暂停原主张的投稿。 |
| 确认有效，留出不复现 | 定位失败任务的业务条件，限定适用范围后重新评估稿件。 |
| 通知交互未发现可靠差异 | 保留 RQ3 负结果；若 S1 → S2 仍有稳定增量，可继续主线。 |
| 主结论存在目标缺证或不可核对 | 修采集并启动独立新批，保留原批完整记录。 |

## 7. 本周开工顺序

1. 建新实验目录和冻结清单，完成最接近文献的差异表。
2. 阅读三条配置的正常入口，画调用顺序与真实可观测状态。明确通知入口、屏障和目标观察点。
3. 固定库存第一格及其五维预期，再补全同簇六格、无变化与授权撤销控制。
