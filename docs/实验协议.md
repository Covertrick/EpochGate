# EpochGate v1.0 实验协议

本协议描述仓库里已经接上的对照，不报告性能数字。假后端和故障场景的成功数不能写成模型或 GPU 上的结论。主实验只读 `configs/frozen.yaml`。开发网格只在 `configs/dev.yaml` 的 `dev_seeds` 上选参，不使用 `test_seeds`。

## 负载

所有主矩阵策略共用：

- 环境：`InventoryEnvironment`，库存和槽位来自冻结配置，`pace=step`。外生增量来自 `plan_exogenous(seed)`，按轮询逐步生效，不按墙钟。
- 到达：`t0` 先到、截止更晚、`strict`；`t1` 截止最早、`loose`；`t2` 居中、`strict`。饥饿负例改成一个稳定的 `loose` 长任务加一个 `strict` 短任务。
- 入口：`run_cell`。`run_once`、`run_freshness_cell`、`demo`、`experiment`、`reproduce` 都走它。

## 基线

| 名称 | 调度器 | 观察 | 取消 |
| --- | --- | --- | --- |
| B0 | `FcfsEnqueueScheduler` | 入队一次，之后忽略 dirty | 不取消 |
| B1 | `EdfFixedScheduler` | 只在没有观测时观察一次 | 不取消 |
| B2 | `FcfsRecheckScheduler` | 入队一次，派发前再查一次 | 不取消 |
| B3 | `StrongComboScheduler` | 版本差、缺观测或 dirty，受预算和间隔约束；刷新当拍不发租约 | 前提为假且可取消 |
| J0 | `NearComboScheduler` | 与 B3 相同的门闩；同一拍可以发租约。打分关闭 | 前提为假且可取消 |
| J1 | `JointScheduler` | 在 J0 的准入上对 `execute` / `refresh` / `wait` 计算 `U` | 前提为假且可取消 |

`EvdfScheduler` 和 `RuleScheduler` 不在主矩阵里。`NearAdmissionScheduler` 仍作为 `near` 对照保留。

消融：

- `event`：`EventRefreshScheduler`。只在缺观测或版本差时刷新。没有临近准入，没有 J1 打分。用来对照 B2 的派发前重查。
- `j1-fair-off`：同一 J1，但 `fair_every_n=0` 且 `fair_weight=0`。

B0、B1、B2、临近准入、`EvdfScheduler`、`RuleScheduler` 的决策顺序和已有 reason 不改。

## 窗口、cohort 与 drain

`run_started` 的窗口终点是 `window_start + T`，`T` 来自冻结配置。

- 有效吞吐：窗口内到达，且在 `min(deadline, window_end)` 前成功的任务数，除以 `T`。窗口结束后的补跑不计入。
- `cohort_success_rate`：分母是全部到达任务，分子是各自截止前成功，含拒绝和超时。
- `drain_duration`：窗口结束到全部终态的秒数。

## 四类过时动作

| `reject_class` | 含义 |
| --- | --- |
| `candidate_stale` | epoch、revision 过时，或缺少观测绑定 |
| `gateway_intercept` | 租约或资格在网关被拦住 |
| `provider_reject` | 版本冲突或库存不足 |
| `stale_commit` | 带检查窗口时提交被接受，但来源版本已经变了 |

`stale_rejects` 是四类之和。观测年龄按 `depends_on` 写入 `observation_ages`，汇总报 max、p50、p95、p99。

token 只有 `usage_source=backend` 才计入浪费。`FakeBackend` 不标这个来源，因此假后端和故障场景上该项为 0，摘要写 `performance_claim=false`。

多种子的 bootstrap 95% 区间由 `bootstrap_ci` 计算，键是有效吞吐、过时动作率和等待 p50/p95/p99。它不写入单条 trace 的 `score_trace`。抽样用标准库，不引入 SciPy。

## 公平份额

B3、J0、J1 的排序键是 `deadline - weight * waited_s`。每 N 次派发，下一个槽给当前等待最久的可执行任务。等待相同时，`loose` 优先于 `strict`。`fair_every_n=0` 关闭份额。Gini 只留在计分里。独立的 `EvdfScheduler` 不使用这个份额。

## 负例

这些用例使用冻结配置上的开关，每条一个 pytest，不进入 CI 的多种子主矩阵。CI 只跑 `pytest`。

- 静态：外生增量为空。不取消。J1 只做入队观察，不因为自己的提交继续刷新。
- 低负载：`max_inflight` 大于到达数。联合策略的完成数不少于 B0。
- 贵观察：观察成本不低于估计服务时间，且推理槽已被占用时，J0 不发刷新，理由含 `expensive observe`。
- 不可取消：`supports_cancel=false`。trace 里没有 `cancel_requested`。
- 突发：短窗口内多次外生变化。每任务刷新次数不超过预算，间隔内的理由含 `refresh interval` 或预算耗尽。
- 饥饿：高频变化的短 `strict` 任务加一个稳定 `loose` 长任务。份额打开时，长任务先于短任务被派发。

变化流的 `drop`、`reorder`、`disconnect` 包在 `changes()` 外面，与 `scenarios/chaos.yaml` 的模型 HTTP 故障分开。断流时把依赖标成未知，并记 `stream_closed`。不把「没有通知」当成稳定，也不编造版本。

## 冻结规则

`configs/dev.yaml` 给出开发种子和网格：刷新间隔、公平权重、`fair_every_n`。`choose_frozen` 在开发行上先取更高的 cohort，再取更少的刷新，再取更大的份额间隔和权重。选出的一组写入 `configs/frozen.yaml`。主实验和 `test_seeds` 只读冻结文件。两套种子不得重叠。

当前冻结文件里的数值是协议选定的稳定组：间隔 0.05 秒，权重 1，`fair_every_n` 4，服务先验 0，窗口 60 秒，库存 3，槽位 1。开发种子是 1、2、3，测试种子是 11、12、13。这不是多种子主矩阵的性能结果。

## 复现

`reproduce` 重跑指标，并比对事件类型、reason 和任务 id。绝对时间可以不同。manifest 记录 `scenarios/chaos.yaml` 与 `configs/frozen.yaml` 的哈希、外生种子和 `fault_injected_count`。不写密钥。
