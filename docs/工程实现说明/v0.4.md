## 1. 目录

| 路径 | 职责 |
| --- | --- |
| `src/epochgate/models.py` | 领域实体、工具规格、调度器可见的裁剪视图。尝试视图含 `refresh_inflight` 与 `premise_holds` |

| `src/epochgate/backend.py` | `InferenceBackend` 与 `FakeBackend` |

| `src/epochgate/faults.py` | 场景加载和 `FaultTransport` |
| `src/epochgate/sqlite_inventory.py` | WAL 库存。默认一条条件更新 |

| `src/epochgate/http_environment.py` | 把环境服务适配成 `EnvironmentAdapter` |

| `src/epochgate/runtime.py` | 组装快照并执行决策。刷新后台进行。禁止直接 commit |

仓库根就是项目根。`src/epochgate` 是 Python 包名（`import epochgate`）。

## 2. 依赖方向

```text
cli / examples / tests / experiment
        ↓
     runtime
    ↙  ↓  ↘
scheduler  gateway  registry / observation / events / refresh_pool
    ↓         ↓
  models   EnvironmentAdapter / InferenceBackend
```

必须守住：

1. `scheduler.py` 不得 import gateway、environment、backend 的具体实现。
2. `scheduler.decide` 只接收裁剪后的 `SchedulerSnapshot`，不持有仓库或 evaluator。快照里的观测没有 payload。
3. 只有 `gateway.py` 可以调用 `environment.commit`。前提探测调用的是 `environment.check`。
4. `scheduler.py` 和 `runtime.py` 的源码里不写具体工具名。配方来自环境的 `default_refresh()`，动作类型来自模型工具调用、后端候选，或工具目录里 `role=effect` 的那一项。运行时按 `ToolSpec.role`（`read` 或 `effect`）分发。
5. 时间用 `time.monotonic()`。
6. 运行依赖：pydantic、typer、httpx、aiosqlite、fastapi、uvicorn。开发再加 pytest、pytest-asyncio。Python `>=3.12`。

公开函数的说明使用中文四段：输入、输出、副作用、失败。

## 3. 运行时在做什么

`Runtime.run` 对已登记任务循环：

1. `changes(cursor)`。新事件把来源标成 dirty，不把环境真值放进快照。
2. 丢掉未在途且已过期的租约，记下 `lease_expired`，下一轮重新准入。观测还在。
3. 对在途且 dirty 的尝试调用 `environment.check`，把 `ok` 写成 `premise_holds`。
4. 调度器只看快照。可以给出 `refresh`、`admit`、`dispatch`、`wait`、`finish`、`timeout`、`cancel`、`reject`。
5. 同一批决策里，`admit` 立即生效。`refresh` 成为后台任务，不挡住同批租约。刷新结束才写入观测并清掉对应 dirty。
6. 派发占一个槽，直到 `max_inflight`。没有槽时 `decision_wait` 的 `reason` 写明在等的任务，以及当前占槽的任务。
7. 模型若返回读工具，把观测正文追加进该 attempt 的会话再请求；若返回写工具，才变成 `CandidateAction` 交给网关。`InferenceRequest.context` 带观测正文，不只是 id。观测失效后的刷新会清空该会话，只留一条由当前观测重建的消息。
8. 网关拒绝里如果是 stale、版本冲突、租约过期或尝试已无资格，且截止时间还在，就新开 attempt，不把任务打成终态。库存不足仍是 `rejected`。列出的观测 id 有缺失时直接拒绝，不用该任务的最新观测顶上。
9. 截止时间已过且没有成功提交，记 `timed_out`。已提交的尝试仍记成功。
10. 取消分成 `cancel_requested` 和 `cancel_acknowledged`。回执原文写入 `reason`，不表示计算已经停止。临近准入只在 `premise_holds is False` 且后端可取消时才取消。

策略：

- `HappyPathScheduler`：不看 dirty，不发取消。现有预约测试仍用它。
- `FcfsEnqueueScheduler`（B0）：只在入队时观察一次，之后按到达顺序派发。
- `EdfFixedScheduler`（B1）：只在没有观测时观察一次，按最早截止再按到达派发。忽略 dirty，不发取消。
- `FcfsRecheckScheduler`（B2）：到达顺序与 B0 相同。准备派发且 `refreshes_used == 1` 时先再刷一次。不发取消。
- `NearAdmissionScheduler`：同一轮可以同时 `refresh` 和 `admit`。已有观测、刷新不在途、租约有效才派发。
- `RuleScheduler`：仍是「先刷新完再准入」，在途 dirty 且可取消就发 `cancel`。对照实验不再用它。
- `EvdfScheduler`：虚拟截止时间是物理截止减去已等待秒数。等待更久的任务排在前面。它不替换上面四条策略。
- 临近准入在估计服务时间已经超过截止时间时发 `reject`。`strict` 租约 5 秒，`loose` 租约 30 秒。冷启动先验默认 0，此时不因估计而拒绝。

故障注入发生在 `HttpToolBackend` 的 HTTP transport，不在调度器里。命中的请求在 trace 里留下 `fault_injected` 和 `fault_kind`。SQLite 的默认 `commit` 是一条 `UPDATE ... WHERE version=?`。`window_s > 0` 才先读再等待再写，用来展示竞态，不表示跨系统原子提交。

没有实现设计文档第 9 节的概率打分。

## 4. 怎么跑

在仓库根目录：

```powershell
python -m uv sync --extra dev
python -m uv run pytest -q
python -m uv run epochgate demo
python -m uv run epochgate experiment --seed 1 --out traces
python -m uv run epochgate reproduce --cell-id b0-seed-1-none --manifest traces/manifest.json --out traces
```

本机没有把 `uv` 放进 PATH 时，用 `python -m uv`。`traces/` 是本地输出，不入库。

`pytest` 不访问外网。HTTP 测试在本机起一个假的 chat completions 服务。

真实模型冒烟读仓库根的 `.env`（`EPOCHGATE_BASE_URL`、`EPOCHGATE_API_KEY`、`EPOCHGATE_MODEL`），只填进当前进程，不改用户环境。三个变量缺任何一个，命令以状态码 2 退出。manifest 只记这些变量是 set 还是 unset。

```powershell
python -m uv run epochgate env-serve --host 127.0.0.1 --port 8080 --db traces/inventory.sqlite
python -m uv run epochgate http-smoke --env-url http://127.0.0.1:8080 --chaos scenarios/chaos.yaml --seed 42 --out results/v0.4
```

`--base-url` 覆盖的是模型地址。`--env-url` 才是库存服务；不传时清单用 ASGI 直连，不另开端口。这次实跑的记录在 [测试记录/v0.4.md](../测试记录/v0.4.md)。

`experiment` 用同一库存种子写出 `b0`、`b1`、`b2`、`near` 四份 JSONL，以及 `manifest.json`。同一种子再跑一次，事件的类型、原因和任务 id 序列一致。绝对时间戳可以不同。`--scenario` 会多跑一个故障 cell；`scenarios/chaos.yaml` 里的延迟是 2–8 秒，默认测试用更短的场景。指标函数 `score_trace` 只读 JSONL。manifest 不记录 API key。

真实端点只在你自己设置环境变量之后访问。密钥不要写进仓库。

## 5. 换后端或环境

实现 `EnvironmentAdapter` 和 `InferenceBackend`，传给 `Runtime(environment=..., backend=...)`。对照实验传入 `FcfsEnqueueScheduler`、`EdfFixedScheduler`、`FcfsRecheckScheduler`、`NearAdmissionScheduler` 或 `EvdfScheduler`。不必改 `scheduler.py` 或 `runtime.py`。

`HttpInventoryEnvironment` 面向 `epochgate env-serve` 起的 FastAPI 服务。进程内 `InventoryEnvironment` 继续服务没有外生 HTTP 的重放。`HttpToolBackend` 可以传入 `fault_plan`，由 `FaultTransport` 包住上游。

环境自己公布 `tool_catalog()`、`default_refresh()` 和 `changes(cursor)`。库存示例是 `InventoryEnvironment`：`observe` 只读，`commit` 按来源版本扣减，外生计划由 `plan_exogenous(seed)` 生成。世界不因推理暂停。同一个已接受的 `action_id` 再次 `commit` 返回原来的 `commit_id`，不再扣库存。

`HttpToolBackend` 只解析响应里的第一条 `tool_calls`。`trust_env=False` 时不走进程里的 HTTP 代理，本机假服务需要这样调用。
