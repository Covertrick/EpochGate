# 实验方法

本文补齐 [正确性修复与补充实验.md](正确性修复与补充实验.md) 和 [E4三问与重复批次.md](E4三问与重复批次.md) 里各批数字的做法。两篇结果文档保留原数。这里不新增测量，也不改 `docs/现行/论文/`。

## 共同约定

统计单位在每节写明。格、批次和单次操作不互相折算。Wilson 区间用 `z = 1.96`，分母是 `1 + z²/n`，四舍五入到四位小数，只描述该批样本。

下列数字禁止相加或相减：

- 旧 360 格与新 120 格。故障组不同，而且旧批次的永久撤销只注入 Full，新批次对三臂都注入。
- 论文冻结稿里的 B0/B1/B2 总时间，与后来 E8 的在线调用。
- 内存库耗时与文件库耗时。
- 旧 E7 的 3 批线程争用，与新 E7 的 30 个独立进程批次。
- 格子里旧的 `tokens.total` 与 input、output。旧 total 把流式帧重复加总，原始帧没有落盘。

密钥从环境读取，结果文件里打码。模型名是 `deepseek-flash`。DSH 使用 Anthropic Messages 根。`.env` 里的 `DEEPSEEK_BASE_URL` 是 OpenAI 兼容根，启动 DSH 子进程时去掉这个变量。

## E1 并发安全与进展

目的：在修复后的 RunLedger 上，看撤销与提交的顺序、两次 `supersede` 是否丢更新、同键重放是否只接纳一次。

材料：每个试验一个新的账本文件和一个新的 EffectSink。进程用 `spawn`。两次 `supersede` 用 `Barrier(2)` 对齐起跑，不用随机交错去规定谁先谁后。随机交错那一格才不设先后。

重复：每个具名场景 100 次。`TRIALS = 100`。

指标：提交状态、sink 接受次数、最终 fencing token、丢更新 `max(0, 成功次数 - (最终 token - 1))`、该次调用的耗时。随机交错只报告这一次样本里谁先发生，不估计总体比例。

命令：`python -m uv run python scripts/runtime_correctness_after.py` 中的 `e1`。原始记录在 `results/runtime/correctness/after/`。修复前对照是 `results/runtime/correctness/before/probe.json`，父提交 `7ac72dd`。

不包含：跨机器，磁盘掉电，模型。

## E2 过期拒绝与合法后继

目的：把旧 token 拒绝和合法后继完成分成两个比率。

因素：正常对齐；只重启控制进程；版本推进中让 sink 镜像写入失败，再补齐；四进程并发推进 20 次。未对齐的 `supersede(run)` 单独观察，不并进完成率。

指标：Stale Rejection Rate 是旧 token 被拒绝的比例。Eligible Successor Completion Rate 是对齐之后新 token 完成的比例。另外记录丢更新和重启后读到的 sink 版本。

重复：并发推进 20 次。其余场景的比率在结果表里是 1，对应脚本里的全数通过，不是另一次 100 次抽样的置信上限。

不包含：文件发布路径。文件路径不读 EffectSink 版本，那个区别放在 E4 的 `version_mismatch` 和离线 `commit_authorized` 测试里。

## E3 文件发布窗口

目的：确定文件发布的决定点是 `claim_publish` 提交成功，而不是 `os.replace`。

程序：四个时刻各做脚本化观察。Claim 前撤销。Claim 后、替换前撤销。替换后、回执前再打开账本并对账两次。回执写上之后再对账。

指标：`published`、目标文件是否存在、文件字节、claim 状态、对账是 `completed` 还是 `replayed`、事件顺序。

重复：结果文档记的是这组观察，不是 100 次。替换后的进程杀死放在 E6。

不包含：把锁内替换说成崩溃原子性。`os.replace` 不在 SQLite 事务里。

## E4 旧 360 格

目的：在三个真实工具任务上，把终态正确、过期写入和合法后继分开计数。

设计：任务 × 故障 × 臂 × 重复。任务是 inventory、approval、coding。每任务 4 个故障，见结果表。臂是 `direct`、`commit_only`、`full`。每组 10 次。共 360 格。

执行：每格一个新进程、一个新工作区和一本新账本。模型 `deepseek-flash`。Node 是当时的 `node-v24.13.0`。这台机器当时没有可用的 `eg-alpine`，三类任务都走进程执行器。编码终态用语法树读取 `value()` 的返回整数，不采用模型自己的成功声明。

世界状态在 `publish.gate.ready` 出现时注入，然后写 `.release`，工具才继续。

| 故障 | 注入 |
| --- | --- |
| inventory 的 `state_change`、`missing_notice`、`version_mismatch` | `stock.txt` 从 3 改为 0 |
| approval 的 `permission_revoked`、`version_mismatch` | `rules.txt` 从 ALLOW 改为 DENY |
| coding 的 `concurrent_edit` | `spec.txt` 从 1 改为 2 |
| `state_change`、`concurrent_edit` 的 Full | 对齐的 `supersede` |
| `permission_revoked`、`publish_failure` 的 Full | `revoke`。旧批次不对其余两臂撤销 |
| `version_mismatch`、`stale_credential` 的 Full | 只 `supersede(run)`，不推进 sink |
| `receipt_loss` 的 Full | claim 成功后、`os.replace` 之前返回，再 `reconcile_file` |
| `missing_notice` | 只改库存，不调用 `supersede` |
| `retry` | 同一内容写两次 |

旧批次的 Direct 和 Commit-only 在门后直接写文件。Commit-only 当时在进门之前 `admit()`，而且撤销和 `supersede` 都没有注入这两臂。所以旧表里这两臂计数相同，不能解释成“资格检查已经被测过且无效”。

终态：库存是 `order.txt` 等于当时的 `stock.txt`。审批是 `decision.txt` 等于当时的 `rules.txt`，撤销后的正确内容应是拒绝，文件不存在则终态为假。编码是 `value()` 的返回值等于规格。过期写入和后继完成沿用 `score_cell`。后继只在 Full、存在 completed 效果、最终 token 大于发放时的 token、且终态为真时计成完成。

命令：`python -m uv run python scripts/runtime_e4_matrix.py`。汇总 `results/runtime/correctness/after/e4_summary.json`。每格在 `results/runtime/correctness/after/e4/cells/`。

## E4 重算

目的：给旧 360 格加上状态向量，不改格子，也不替换原来的 `terminal_correct`。

程序：`scripts/e4_audit.py` 只读格子。`task_success` 复制 `terminal_correct`。`stale_effect` 复制 `stale_effect_accepted`。`successor_completed` 复制 `eligible_successor_completed`。`safety` 是没有过期写入。`correct_abstention` 要求故障不是 `receipt_loss`、资格已撤销、目标文件不存在、且没有过期写入。`outcome_known` 只看效果行、对账和拒绝事件。对账 `unknown`，或 `DISPATCHED` 且没有回执，就是未知。文件还在不能单独算已知。`unknown_fraction` 原样保留。

`receipt_loss` 增加注记 `claimed_before_replace`，格子字段不改名。`version_mismatch` 增加机制标签 `file_successor_token_refresh`。

命令：`python -m uv run python scripts/runtime_e4_rescore.py`。输出 `results/runtime/correctness/e4-audit/rescore.json`。

## E4 功能验收和 120 格重复

目的：先确认四组故障上三臂的机制差异，再在冻结协议上做一批初步重复。

网格：`approval/permission_revoked`、`inventory/state_change`、`inventory/missing_notice`、`inventory/claimed_before_replace`。三臂。验收每格 1 次，重复每格 10 次。

与旧 360 的注入差异：`permission_revoked` 在开门时对三臂都 `revoke`。`state_change` 仍对所有臂修改 `stock.txt`，`supersede` 仍只调用 Full。`claimed_before_replace` 的 Full 在崩溃返回后调用 `recover_claimed_publish`，调用者持有同一本账本、`run_id` 和幂等键。`receipt_loss` 这个旧名字不出现在新网格里。

预期写在 `scripts/runtime_e4_smoke.py` 的 `expectation()`，跑完不回改。回合结束原因 `kind=error`，或插件导入失败，该格失败。第一轮验收因为撤销只注入了 Full 而作废，目录已清空，不与通过的验收或重复混合。

通过的验收是冻结点。父提交 `847165b`。工作区协议文件的 sha256 前 12 位写在结果文档里，重复期间这些文件没有再改。重复脚本在验收摘要的 `passed` 不为真时直接退出。

统计：重复的单位是格。每组 n=10。报告命中数和该组的 Wilson 区间。四组加总的每臂 40 格可以做描述，臂级区间重叠，不把它当成已经分离的总体差异。没有做功效分析，也没有预注册。

环境：Node v24.14.1，进程执行器，模型 `deepseek-flash`。这两批启动时 `docker_available` 为假，摘要里的 `docker_note` 保持未测。

命令：

```powershell
python -m uv run python scripts/runtime_e4_smoke.py --rounds 1 --kind smoke --out results/runtime/correctness/e4-smoke
python -m uv run python scripts/runtime_e4_smoke.py --rounds 10 --kind repeat --out results/runtime/correctness/e4-repeat --require-smoke results/runtime/correctness/e4-smoke/summary.json
```

本机访问模型时设置 `HTTPS_PROXY`、`HTTP_PROXY` 和 `NODE_USE_ENV_PROXY=1`。这是网络条件，不是实验因素。

## E5 效果身份

目的：划定这个本地接收端在重复提交、载荷变化和回执丢失时的状态。

程序：同键同载荷；同键不同载荷；重启后再用不同载荷；接纳之后、回执之前 `SystemExit(86)`；外部系统不可条件查询时 `seal_unconfirmed_external`；本地 HTTP 在接纳后断开；本地 HTTP 返回不可用。

指标：状态是 `replayed`、`conflict` 还是 `unknown`；保存的 payload 是否仍是第一次；sink 接受次数；客户端看到的异常类型。

重复：结果表是这些脚本化检查的结果。它不估计任意 HTTP 服务的 exactly-once。

## E6 强制终止

目的：区分受控退出、操作系统杀掉进程、以及未提交事务回滚。

程序有三步，每步一次。`run_fault(..., "after_sink")` 以 `SystemExit(86)` 停在接纳之后、回执之前，然后对账。另一个进程在 sink 接受次数变为 1 之后被 `process.kill()`，当时账本还没有这条效果行，重开后再对账。第三个进程在未提交事务里改 token，睡眠后被杀掉，重开后读 token。

指标：退出码、对账决定、接受次数、杀死前的账本相位、重开后的 token。

不包含：断电，磁盘持久性，内核崩溃。`TerminateProcess` 只表示进程消失时已经接纳的 sink 行还在，未提交的 SQLite 事务不在。

## E7 旧的控制面耗时

目的：给单机控制操作一个耗时数量级，并看同一数据库上多线程 `supersede` 的一次争用样本。

内存库：单连接。操作是读 Run、claim、commit、replay、reconcile、supersede、revoke。每种 60 次，单位毫秒。`RunLedger()` 不传文件路径，所以这列不是持久化吞吐。

文件库：并发 1、2、4、8、16。每档 3 批。同一进程里每个线程自己的连接，屏障对齐后只计 `supersede`。同一批的样本被放进一个分布。并发 1 只有 3 个点，p99 不稳定。失败数单独记录。

不包含：进程启动。这列也不与内存库相减。主机是一台 Windows 机器。

原始记录：`results/runtime/correctness/after/e7.json`。

## E7 批次

目的：把复现单位改成批，并记下实际的日志参数。

程序：`scripts/runtime_e7_batches.py`。不调用 `journal_mode` 或 `synchronous`，只读连接上的值。每个正式批是一个新的 SQLite 文件和一个新进程。进程内按并发开连接，每连接一次 `supersede`。并发只测 1 和 16。每个并发度先跑一批预热并丢掉，再测 30 批。延迟从连接已经打开之后的调用算起。进程墙钟另记，不进入 supersede 延迟。一批的吞吐是该批完成次数除以该批墙钟。

报告：30 个批次中位数的分布，以及全部操作样本的经验分布。操作 p99 标注为操作分布。并发 16 的 480 个操作不写成互相独立的确认试验。

原始记录：`results/runtime/correctness/e4-audit/e7_batches.json`。不覆盖 `after/e7.json`。

## E8 端到端

目的：看一次短模型调用旁边，本地提交和对账占多少墙钟。

离线轨迹：60 次。不调用模型，所以模型时间和排队时间记 0。顺序是 claim、`commit_authorized`、reconcile。载荷是固定的 `OK`。

在线：先探测一次 `deepseek-flash`。探测失败则整段记为 blocked，不编造时间。探测成功后再对 B0、B1、B2 各做 20 次。每次提示都是回复单个词 OK，`max_tokens=16`。B0 只计模型。B1 再 `commit_authorized`。B2 再 reconcile。控制面时钟包住这些本地调用，不包住模型往返。

不包含：论文冻结稿 `docs/现行/论文/数据/01-主实验/tables.json` 里那次公平开销。那次总时间中位是 0.878、1.034、1.067 秒，步骤更多。两组都保留，不取差。

原始记录：`results/runtime/correctness/after/e8.json`。

## 容器与宿主发布端

目的：比较“读入内存后再写回”和“按路径替换”在暂存被事后修改时的落盘字节。

环境：Docker Desktop 4.84.0，引擎 29.6.2，OSType linux。WSL 发行版 `eg-alpine` 由 Alpine 3.21.9 minirootfs 导入，其中的 `docker` 指向这个引擎。镜像 `python:3.10-slim`，digest `sha256:6ff506466f8b1e981719b468cc0023b8ef000b983cdec0eafe119d01f379e31d`。容器参数沿用 `start_container`：非特权、`network=none`、无挂载、内存 256m、pids 64。发布用户是 uid 1001，工具用户是 uid 1000。

集成测试：

```powershell
python -m uv run pytest packages/runtime/tests/test_security_boundary.py packages/runtime/tests/test_linux_task.py packages/runtime/tests/test_measurements.py -q --tb=line
```

这次结果是 9 passed，91.52 秒。断言包括：发布用户不是 root；容器内看不见 Docker socket；锁定后工具用户不能写 `/workspace`、能写 `/scratch`；忽略 SIGTERM 后可被 SIGKILL；`value()` 为 0 不通过、为 1 通过；符号链接暂存和 `../` 路径不发布；同一幂等键第二次是 `replayed`。

读竞争测量：`scripts/runtime_container_probe.py` 调用 `measure_container_read_race` 和 `measure_host_read_race`。原始字节固定为 `hashed-bytes-v1`。读完之后再替换或截成空文件。容器侧记录已发布字节的摘要是否仍等于读入时的摘要。宿主侧记录 `publish_file` 的状态、回执和落盘摘要。两边都声明没有覆盖内核读取窗口。

输出：`results/runtime/correctness/e4-audit/container_measurements.json`。

不包含：模型任务重跑，内核级逃逸，生产编排器。

## 离线协议测试

目的：把模型批次没有覆盖的协议边界留在确定性测试里。

`packages/eg-workspace/tests/restricted-publish.test.js` 三例：Direct 不调用 `admit`；门打开时资格已经撤销则 Commit-only 不写；`admit` 返回允许之后才撤销，则写入仍然发生。

`packages/runtime/tests/test_publish_contract.py` 覆盖 Claim 后替换前的恢复、替换后只补回执、暂存消失则 `unknown`、目标冲突不覆盖、错误的 `run_id` 或陌生字节不能完成发布、已完成摘要冲突、未完成摘要冻结、外部写入者被覆盖、两个协作进程只发布一次，以及 sink 落后时 `commit_authorized` 以 `version` 拒绝、对齐后后继完成。

`packages/runtime/tests/test_e4_audit.py` 固定重算规则和验收预期，包括嵌套 usage 不重复加总，以及 `bug.py` 仍是 `return 0` 时不得把结果算成已知。

容器测量之后这次是 21 passed（11.49 秒）和 3 passed。它们不打模型。
