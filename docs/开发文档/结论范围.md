# 结论范围

这六项限制写在读完 v4 提示审计之后。已有 JSON 不改。

## 隐藏测试

v4 九个任务的模型都看到了隐藏测试运行后的失败行。确认集初始通过 4、后继通过 3，分母 6，保留为固定失败反馈下的修复。严格隔离是 `Coding-v4c`。同一六个任务在撤下失败行之后，初始通过 4、后继通过 4，分母仍是 6，目录 `results/runtime/correctness/v4c-isolated/`。两批不相加。v4c 记录的源码提交是 `c5fd4603739019c44736844ccc0da77d87a70098`。

## 创新性

不声称首次发现 stale 不等于 unsafe，也不声称首次把任务成功和可验证效果分开。多出来的是同一次受控运行里的四列，而且这四列不能互相代替：旧凭证是否被拒、内容是否仍被独立测试判定为有效、拒绝后合法后继是否完成、Claim 字节与物理字节是否一致或必须停在 UNKNOWN。

## 强基线

Outbox 只在同库事务合同里与 Full 比较版本检查和幂等插入。文件发布、Claim 到字节和 UNKNOWN 不在那个合同里。见 `docs/开发文档/Outbox对照边界.md`。

## 可复现

`results/paper/implementation-freeze.json` 在工作区仍脏时保持 `reproducible_commit` 为 false。代码和这批结果进入同一个提交之后，才把该提交写成复现点。环境锁在 `results/paper/environment-lock.json`。v4 不因为要变干净而重跑；重跑会把已经泄漏的失败行再送一遍。干净的新测量是 v4c。

## 统计与语义冲突

确认集六个任务不是跨项目结论。v4b 的 `raise RuntimeError` 是注入式故障，不是开发者并发修改的分布。能进入内容失效分母的只有两格。B2 和 B3 在这两格上拒绝旧效果，是 fencing token 检查的直接结果，不是新的语义守卫。v4b 的用处是把“版本错误”和“内容失效”分成两类，并记录后继是否被接纳。真实历史提交 `0fcdde9c` 打到 `code-more-itertools-20c4ee5c` 的 base 上之后，旧的黄金补丁仍然通过隐藏测试。版本检查仍会拒绝它。同一提交打到 `172bcb3c` 上时，旧补丁不能应用。记录在 `results/runtime/correctness/v4b-historical/summary.json`。

## 跨 Runtime

不主张这套方法已经迁移到第二个 Agent 运行时。LangGraph 的编码结果仍是历史补丁驱动的冒烟，Claim 为 `NOT_SUPPORTED`。同键一次接纳属于外部接收端。履约侧已有的通知缺失、响应丢失和中断重放只说明适配器能观测这些故障，不与 EpochGate 的 Claim 恢复等价。
