# EpochGate 2.0 实验方案

协议日期：2026-11-06。测量合同在 [measurement_contract.md](测量合同.md)。准入在 [case_admission.md](案例准入.md)。

## 问题

H1：在真实历史更新下，过期证据误用和无谓重做是不是可重复的结构性差异。比较相关、无关和不确定更新，也看文件依赖、跨模块关系、变更通知和工具证据是否对应不同错误。

H1 成立还不够。还要说明错误主要不是来自 Clean 任务本身做不对、变更不能应用、后状态评分不可靠、工具输出和文件不一致，或标注错了。相对 SWE-Shift，还要指出新的解释维度。

H2：LLM Dependency 是否比 Re-read and Retest 和 Static Dependency 更少地丢弃仍然有效的工作，同时任务正确性不下降。只比 Global Reset 更省，不算 H2 成立。

## 臂

同一 DSH Agent Loop、同一个 `deepseek-flash`、同一组工具和同一预算。变化的是 `eg-dependency-policy` 的配置。

- Global Reset：仓库版本变化后放弃当前工作并重新开始。
- Re-read and Retest：更新后重新读取相关材料并重新测试。
- Static Dependency：按明确的文件或结构化依赖做选择性失效。
- LLM Dependency：由模型判断哪些证据过期。判断本身的调用计入成本。
- 诊断臂：不主动处理更新。
- Oracle：外部评分上界。使用隐藏依赖。报告时标明额外信息，不与可部署策略并列为公平基线。

## 一次 episode

1. Linux 容器恢复指定 `base_commit`。容器里的 Git 历史不含未来修复。
2. DSH 阅读、搜索、测试并修改。
3. 在 turn 已经结束、没有未完成工具副作用时写入 checkpoint。
4. 控制器把已准入的历史变更应用到隔离工作区，并给出协议规定的通知。
5. Agent 继续。记录刷新、旧证据使用、修改和候选 patch。
6. 外部评分读取原始测试、变更后测试、证据规则和工作保留不变量。

Clean 分支不注入变更，用来确认基础修复能力。Clean 做不对时，不把 Changed 上的失败解释成状态依赖错误。

## 复现等级

- R1：同一 Git SHA、同一镜像 digest、同一依赖锁。
- R2：同一输入、工具输出和状态转移。靠事件日志、原始模型响应和环境快照。
- R3：同一评分、汇总和图表。靠冻结的评分器、数据哈希和统计脚本。

Trace Replay 服务 R2 和 R3 的审计。Fresh API Rerun 服务模型行为是否稳定。DeepSeek 在线响应不保证逐 token 相同。

每次运行保存 DSH 版本、插件版本、模型标识、采样参数、镜像 digest、任务哈希、两个 Git SHA、Session 事件、工具结果、最终 patch 和评分。密钥不在其中。

## 数据污染

公开 issue 和参考修复可能已经进入模型训练数据。正式论文要写这个限制。能用的敏感性分析是较新的独立任务，或训练截止日期之后的历史隔离。M0 不为此增加第二种模型。

## 停止

- 五个完整事件对不存在：停在数据报告。
- Clean 能力不足：先改任务或模型适配，不解释动态状态。
- 只有 Global Reset 更浪费：工程对照。
- H1 有新维度、H2 失败：可以写测量稿。
- H1 和 H2 都没有新差别：不写创新论文。
- H1 成立且 H2 在强基线下同时改善安全与效用：才讨论评测加方法。
