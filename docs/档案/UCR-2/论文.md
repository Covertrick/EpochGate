# UCR-2.1

日期：2026-11-06。协议在 [UCR-2.1实验方案.md](实验方案.md)。数字在 `results/experiments/ucr2/summary.json`。

**插值留出上的 Gate A 和 Gate B 都不通过。UCR 算法线在这里收口。** 没有跑 F17–F20，也没有为这条协议再跑 vLLM。不写投稿句。

UCR-1 的封存结论不变：那一版生成器没有构成有效评估。UCR-2.1 修正了生成器并通过了 Gate A0，然后在新的留出集上仍然没有证明非 Oracle 的区间加 probe 优于点估计。

## 拟合之前

Gate A0 通过。已生成 token 与 \(S\) 的偏相关是 −0.98，\(1/r\) 与 \(S\) 的偏相关是 0.75。高 token 组的真实 \(S\) 更短。reserve 与 query 的平均 \(S\) 相差超过 20%，早、中、晚的平均 \(C\) 递增。开发加校准里，真实成本接近的 trace 占 38.5%；其中 probe 价值为正的占 25.1%，为负的占 28.4%。高代价类的价值全部低于 2 秒预算。有信息类的 Oracle 动作改变率是 0.37，无信息类是 0。AlwaysContinue 的失败率低于 0.15。

估计器在打开 F13 之前锁定为「线性趋势加树残差 + group-conditional CQR」。它在校准格上达到了预登记的不欠覆盖。pooled CQR 没有达到。锁定之后没有因留出结果改回另一种模型。

每族 400 条。后悔相对 Cost Oracle。bootstrap 10,000 次。ExpectedValue 与 Point 的后悔相同：有效谓词上的经验失败概率低于 0.5，这条基线退化为点估计比较。

高 token 组的区间更窄，这一点成立。F16 的 \(S\) 经验覆盖率是 0.79，Gate A 因此不通过。这里只报告 Wilson 下界，不把它写成覆盖保证。

Full 在四族上都比 Point 和 ExpectedValue 更差，差的 bootstrap 下界全部小于 0。probe 确实出现在重叠区，四族的区间外 probe 数是 0，probe 后动作改变率约 0.17–0.22。去掉 probe 后，四族的代价都上升。这只说明 probe 比「同一套宽区间、但不许 probe」好，并不能抵消宽区间相对点估计多出来的后悔。选择命题的违反数是 0，失败率也没有超过 AlwaysContinue 加 0.02。Gate B 仍然不通过。

## 收口

Gate A 失败说明这组估计器和分组校准没有在全部插值族上达到预登记覆盖。Gate B 失败说明区间加 probe 没有带来额外收益。外推压力和 vLLM 按协议不再运行，因此本协议不新增 Gate C 记录；UCR-1 里已有的安全闭环仍然有效，但不构成算法创新。

4.0 仍是队列现象测量。5.0 仍是安全 Gateway 和复现失败。UCR-1 与 UCR-2.1 都没有证明非 Oracle 不确定性策略的额外收益。不再加族，不再换模型。
