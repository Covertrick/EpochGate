# 阶段一实验协议

冻结时间：2026-11-02。基线提交 `6de2721db84ed73c2c855291ee0c554972b40f93`。矩阵跑在这份提交之上的未提交工作树上。工作树再改代码时，新行不得追加进已经写过的 `results/real/matrix.jsonl`。

模型：`deepseek-chat`，地址 `https://api.deepseek.com/v1`。提示词版本 `phase1-words-v1`。系统提示要求在解释之后用整数 `qty=1` 调用 `reserve`。任务文本要求先写至少 N 个词，再调用工具。`N` 是实验条件，不是实际词数。实际词数记在 `actual_words_before_tool`。

超时：任务截止 120 秒，HTTP `timeout_s` 180 秒，Runtime `max_steps` 8000。密钥只在进程环境里。

## 矩阵

每格计划 5 对。种子只是记录编号，不保证模型复现。每对使用相同任务文本、工具、库存初值 3 和延迟，各自独立环境。每对用 `random.Random(seed)` 决定先 A 还是先 B。

- A：300 词，延迟 0.1 / 0.5 / 1.5 秒，种子 101–105、106–110、111–115。
- B：延迟 0.5 秒，50 词种子 201–205，800 词种子 301–305。
- C：300 词，延迟 0.5 秒，3 个任务，`max_inflight=1`，种子 401–405。三个任务进入同一个 Runtime，共用一个库存。撤销目标是第一个产出增量的尝试。另外两个任务保持相同到达顺序。

A 不断开。B 在资格撤销时关闭响应。库存在目标尝试的首个增量之后延迟指定秒数改为 0。

## 排除和汇总

`pair_status` 为 `trigger_not_fired`、`unexpected_tool_call`、`model_error`、`request_timeout`、`cancel_error`、`protocol_error` 的对，不进入节省率中位数。未触发的节省率是 null，不填 0。比率按对计算后再取中位数、最小值和最大值。分母为 0 时比率为 null。差值为负时保留。

`model_error` 只用于传输失败，原因以 `http_`、`parse_error` 或 `stream_closed` 开头。重规划写完但没有调用工具，原因留在 `backend_failures`，这一对仍可是 `completed`。目标尝试没有 `tool_call_delta` 时，`revocation_position_ratio` 为 null。B 臂关掉响应之后看到的词数是被切断的前缀，不是模型本来会写完的长度。

20% 和 5% 是预先设定的项目决策门槛，不是显著性阈值。落在中间标成不确定。B 的撤销后增量经常多于 A 时先诊断，不归进三个方向。

本地增量是 `token_delta` 和 `tool_call_delta` 的条数，不是 tokenizer 的 token。供应商 completion 混有重规划，不能当成被切断那次的账单。

## 预检

各长度一次，不进入 `matrix.jsonl`。原始行在 `results/real/preflight.jsonl`。三次都提交成功，库存从 3 到 2，都没有靠近 120 秒截止。

| 目标词数 | 端到端秒 | 工具调用前实际词数 | 是否纳入 |
| --- | --- | --- | --- |
| 50 | 1.81 | 91 | 纳入 |
| 300 | 3.52 | 316 | 纳入 |
| 800 | 6.80 | 640 | 纳入 |

800 词的实际输出是 640 词，短于目标，但 6.8 秒远低于截止，所以这一格留在正式矩阵里。分析时用实际词数，不把目标词数当成生成长度。

第一次正式开跑在 0.1 秒和 0.5 秒两格的中途停下。当时把「重规划没有工具调用」记成了 `model_error`。那些行在 `results/real/matrix_aborted.jsonl`，不进入汇总。

第二次开跑又停了。读工具的后续请求把观测列表直接放进 `content`，接口返回 422，缺 `type`。流正常结束但没有工具调用时，异常分支还引用了没有导入的 `json`，进程退出。这两处修正之后才写正式矩阵。中断行在 `results/real/matrix_aborted_422.jsonl`。
