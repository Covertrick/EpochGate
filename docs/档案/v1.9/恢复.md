# v1.9 恢复与副作用

日期：2026-11-02。

## 确定性故障

`tests/test_v22_measure.py` 里五类故障各 50 次，顺序由种子打乱：

1. 撤销之后旧 attempt 与新 attempt 以两种顺序提交。旧动作不被接受，库存只减一次。
2. 两个 attempt 抢同一份库存。只有一个 `reserve` 被接受。
3. 工具提交成功后丢掉回执再交同一个 `action_id`。第二次返回原提交，不再扣库存。
4. 恢复之后再次把库存打掉。若这次失效发生在提交前，用旧版本提交会被拒绝。
5. 重放 `attempt_begun` 和 `eligibility_revoked`。进程重启标记和重复的开始事件不会把已撤销尝试恢复成有资格。

这 50 次覆盖的是这些网关和重放顺序，不是任意外部 API 的恰好一次。

## 真实可恢复库存

文件 `results/experiments/v1_3/recovery/real.jsonl`，短/中/长各 20 个种子 × A/B/C，共 180 行。完成指有一次有效提交，且旧 attempt 没有提交。传输错误 0。旧提交 0。重复副作用 0。

| 长度 | A | B | C | A 比 C 高多少 |
| --- | ---: | ---: | ---: | ---: |
| 短 | 0.85 | 1.00 | 0.90 | −0.05 |
| 中 | 1.00 | 1.00 | 0.95 | 0.05 |
| 长 | 1.00 | 0.95 | 0.90 | 0.10 |

预先写下的界限是 C 比 A 低不超过 10 个百分点。三个点估计都在界限内。长任务正好低 10 个百分点，配对差的重采样区间是 [−0.25, 0.00]，所以不能把长任务说成已经被区间钉在界限以内。
