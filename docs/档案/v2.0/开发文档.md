v1.0 已经能重放版本隔离、唯一提交网关和取消分级。它还不是生产运行时，也还没有研究结论。v2.0 补两类缺口：让研究问题能被证据回答；让取消、过载和多进程这些仍停在声明或剧本里的路径变成真的传播链。两件都没做完之前，不把仓库说成能承载真实流量，也不把联合调度写成已经提高了吞吐。

代码名保持原样。下面用中文说明它们做什么。

## 1. 不要重复当成已经有的三件事

- 任务登记和观测存储在进程内存里，不在数据库里。库存库已有预写日志、立即事务和五秒锁等待，只保证库存行不丢、不重复。
- 事件序号是进程内递增。可选的数据库双写不是跨进程的全局顺序。
- 推理提交返回句柄，随后给出受理、完成或失败。这不是词元流。取消一条非流式请求，看不到生成循环是否停止。非流式后端继续声明资源回收不可观测。

演示命令和固定解释轨迹只服务回归，不能当作研究结果。冻结配置里的数字还没有在开发种子上扫过网格。

## 2. 目标

一条轨道没完成，不能用另一条轨道代替。

| 编号 | 目标 | 完成时能看到什么 |
| --- | --- | --- |
| 研1 | 在真实模型延迟下，失效计算有没有可确认的词元浪费 | 静态低变化时模型能订对库存；变化间隔与推理耗时同一量级；四类过时动作和后端用量写在原始轨迹里 |
| 研2 | 联合打分能单独关掉，从而和临近准入对照分开 | 服务先验为 0 时，不再把“能按时完成”写成恒真；公平槽也能单独关闭 |
| 研3 | 负例和两支缺的消融给出前后差值 | 有效吞吐、浪费词元、等待九十九分位，而不是只有“测试通过” |
| 工1 | 流式取消能停住生成循环 | 见第 4 节 |
| 工2 | 准入和事件日志有界 | 过载时拒绝，进程不因队列撑满内存退出 |
| 工3 | 两个进程不能同时推进同一会话 | 恰好一个准入成功，另一个得到租约冲突 |
| 工4 | 轨迹仍是复现依据，另可导出调用链 | 测试能解析根跨度和子跨度。持续集成不启动外部追踪界面 |
| 工5 | 配置有版本，进程能探活，并在终止信号后停收新任务 | 版本不认识就拒绝启动 |

具身迁移只保留对应关系：库存版本对应技能副作用的版本，迟到输出对应任务中止后的完成信号。本版不做控制器和感知。

## 3. 顺序

先做工1和研1。没有这两组结果之前，不接第二环境，不接 vLLM 或 SGLang，不把联合打分写成贡献。

研1若显示浪费可测，再做研2和研3。若浪费接近零，不做“证明联合打分更好”，改走第 6 节的第三种论文，研3仍要做。工2和过载负例一起做。工3、工4、工5不阻塞论文数据。

不做：训练模型、多图形处理器内核、集群控制器、租户计费、机器人低层、官方榜单，以及为了维持题目再加一套学习型调度器。

## 4. 研究怎么做

指标、窗口、同批成功率和四类过时动作沿用实验协议，不另起口径。统计单位是一次运行或一个种子。开发种子 1、2、3 选参，测试种子 11、12、13 只跑冻结后的那一组。密钥只放在仓库根的环境文件里。

能力基线用一个兼容的非流式模型。静态、槽位足够时，它必须能读库存并提交正确数量。做不到就换模型或把任务收成一次读取加一次预约。用量里要有后端来源和供应商返回的词元数。假后端继续不标这个来源，浪费词元保持为 0。

外生变化的间隔取这次测到的推理耗时中位数附近。具体秒数写进当时的实验记录，本文不预填。变化远快于推理，或推理延迟接近 0，都不算合理负载。

联合打分要改成：完成项用已观测的服务时间对剩余截止；没有样本时用冻结先验。先验为 0 表示还不知道要多久，此时不写成恒定能完成，也不因此拒绝。可用项仍只用已经收到的变化。等待的效用保持 0。这不是最优策略，版本变化率也不是真实失效率。

第一张结果表只比较入队一次、最早截止、派发前重查、事件门闩、临近准入和事件刷新。联合打分进入表格的条件，是关掉打分和关掉公平槽都会改变决策理由。

负例要报差值的有：静态、低负载、贵观察、不可取消、突发、饥饿、过载。另外两支消融是：去掉早期取消但仍丢弃旧结果资格；版本变化不再按依赖过滤，只看来源是否变脏。

## 5. 工程怎么做

### 5.1 流式取消

保留现有提交接口。流式事件增加词元增量和工具调用增量。决定取消时，先使该次尝试失去资格，再关闭流或取消对应任务，让取消异常进入生成循环。供应商有取消端点就调用，回执为已接受。没有端点就关闭连接，回执为已确认，证据写明是连接关闭。只有生成循环确实不再产出，才记录资源已回收。半截工具调用不得交给网关。

验收：假流式后端计划生成超过五个词元，第五个之后取消。一秒内不再有新的词元增量。轨迹里依次出现取消请求、取消确认、资源已回收。没有成功提交。

服务端是否释放键值缓存，不作为本版验收，论文也不写显存节省。

### 5.2 有界队列

等待中的尝试达到上限就不再登记，拒绝原因是准入队列已满。刷新池并发槽满时只等待，理由写明池已饱和。事件缓冲满时，可以丢弃重复的等待记录并计数。运行开始和结束、提交、拒绝、取消、资源回收、任务终态不得丢弃。计分增加队列深度、背压拒绝次数和丢弃次数。

### 5.3 多进程会话

会话状态写入数据库，不假装登记表已经在库里。更新条件带会话标识和租约纪元，影响行数为 0 就返回租约冲突。写事务立即开始，锁等待五秒。跨进程序号用库自增。长推理用心跳延长租约，心跳不能救活已经失去资格的尝试。

验收：两个运行时对同一会话并发准入，恰好一个成功。不同会话可以并行。库存的二百行测试仍然通过。

### 5.4 追踪、探活和退出

离线复现仍以事件轨迹为准。调用链是附加导出：每次尝试一个根跨度，观察、刷新、推理和提交是子跨度。没有导出器时跨度标识为空，旧的重放比较保持不变。持续集成只解析导出的文件，不启动外部界面。

冻结配置增加配置版本，清单记录它。代码不认识该版本就拒绝启动。环境服务增加存活检查，确认库存库可写。收到终止信号后停止登记新任务，等待在途尝试直到截止或冻结的宽限，写出未终态，再关闭数据库。镜像用锁定的依赖，不放密钥。金丝雀任务类不进入主矩阵，除非以后单独写进协议。

## 6. 论文形态

只走数据打开的那一种。标题都还不是主张。

| 数据 | 形态 | 暂定标题 |
| --- | --- | --- |
| 浪费可测，且联合打分与临近准入的区间分开 | 测量加机制 | 新鲜度准入在什么条件下有用 |
| 浪费可测，两者区间重叠 | 负结果 | 起作用的是新鲜度门闩，不是效用打分 |
| 合理负载下浪费接近零 | 系统经验 | 真实推理延迟下，失效计算并不常见 |

可以写的只有：声明负载下的浪费量级；同一到达和种子上，门闩相对入队一次、派发前重查的区间是否跨过零；关掉估计、公平槽或早期取消后差值是否消失。

不能写：全局最优、取消等于显存已释放、没有通知等于世界稳定、库存名次等于第二环境名次。样本量看开发种子的方差再冻结，本文不预写种子个数或增益比例。

相邻工作要承认一致性提交、推理期放弃、按价值刷新，以及上下文掩码和多智能体浪费诊断。若本文有缝隙，只讨论共享推理槽上刷新时机与注定失效的计算量，并且必须有研1的词元分母。
