## 回放数字

带外 97,200 条里，UncertaintyAwarePolicy 的动作标签和合成 Oracle 一致。带内 24,300 条都是 `continue/defer`，没有一条被回放成中止。旧提交和重复副作用都是 0。

这 100% 是同一套确定性公式的自洽：估计值由真实 \(C/S\) 和给定误差算出，Oracle 用的也是这些标签。它不是语义检测器的准确率。

旁观者 P95 的配对差（正数表示不确定性策略更短），每格 4,050 对：

| 对照 | 负载 | 差的范围 | 相对 |
| --- | --- | --- | --- |
| 有害，对 AlwaysContinue | 中、高，五个 \(\rho\) | 1.15–2.44 秒，区间下界都大于 0 | 2.5%–5.6% |
| 有害，对 AlwaysAbort | 全部 | 0 | 规则在谓词失效时就是中止 |
| 无害且 \(\rho\ge 1.25\)，对 AlwaysAbort | 中、高 | 0.63–2.47 秒，区间下界都大于 0 | 1.6%–5.8% |
| 无害且 \(\rho=1\)（误差带） | 中、高，对 AlwaysContinue | 0 | 带内占用等于继续 |
| 无害且 \(\rho=1\)，对 AlwaysAbort | 高 | −0.043 秒，区间 (−0.090, −0.005) | 带内不切换，比总是中止略慢 |
| 低负载 | 全部 | 0 | 到达间隔 20 秒，队列没有排起来 |

低负载是空结果。中、高负载上，规则优于「当时更差的那个固定策略」，相对差低于 4.0 用过的 10% 门槛。它没有在同一格里同时优于继续和中止。完成率在低负载是 1；中、高负载五种策略的均值都在 0.93 左右，最低 0.472，忙时的等待包含观察窗封顶。

## 运行时闭环

240 个 attempt 里四种动作都出现了：中止 60、继续、defer、交给 Gateway。库存被降到 0 之后决策是中止；候选形成后 Gateway 接受；`plan_epoch` 推进后，旧候选 60 次全部拒绝。过期提交 0，失效尝试上的提交 0。

60 次中止都记下了客户端断流回执，等级是 `UNKNOWN`，`reclaimed=false`。其中 59 次采样时 `vllm:num_requests_running` 仍是 1。这不能写成服务端已经停止，也不能写成 GPU 或 KV 已回收。
