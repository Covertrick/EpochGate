# EpochGate 5.1 论文结果确认合同

日期：2026-11-04。这不是新的研究方向，也不扩大实验矩阵。5.0 的 DeepSeek 确认性已经给出客户端可观察的同向改善。本阶段只回答三件事：这组 DS 结果能否独立复现；本地放槽和后端释放之间实际发生了什么；相对 Retire、Vesta 和其他近邻，它是否构成可发表的测量增量。

5.0 数字、协议和禁止项仍以 [项目开发文档5.0-方向A.md](../v5.0/弃用-开发文档方向A.md)、[论文5.0-方向A-弃用.md](../v5.0/弃用-论文方向A.md) 和 [v5.0-确认性-DS.md](../v5.0/弃用-确认性-DS.md) 为准。不重跑、不改写 7000–7049 的已封存 JSONL。

## 1. 已经可以写进论文的句子

在 DeepSeek V4.1-Flash（API 名 `deepseek-flash`，thinking 关闭，`max_tokens=512`）的当前配置下，撤权后立即停止本地读取并释放 Runtime slot，相对继续持有本地 slot 直至流结束：

- 中负载与高负载的旁观者本地槽等待都下降，相对改善 21.4% 与 11.2%，bootstrap 2.5% 分位大于 0，两档都过预登记工程门槛。
- 端到端差在两档都为正，区间都不含 0。中负载相对 12.3%，过门槛。高负载相对 8.6%，绝对差为正，**没有**过「相对至少 10% 且区间下界大于 0」的完整门槛。
- 槽等待与端到端同向变短。原先期待的 local/e2e 分叉没有出现。这否定的是 D2 的那一种现象，不是 5.0 测量本身。
- 服务端停止状态全部是 `unknown`。不能把结果归因于服务端计算或 KV 回收。

配对差定义为 \(\Delta = G0 - G2_{\mathrm{local}}\)。正数表示 G2-local 更短。

## 2. 这组结果不能证明什么

G0 与 G2-local 同时改变了继续读取还是停止读取，以及 Runtime slot 何时释放。断流还可能让服务端取消、继续或延迟取消。0.86–0.92 秒的端到端改善兼容：

| 解释 | 内容 |
| --- | --- |
| A | 本地队列：G2 更早放槽，旁观者更早开始 |
| B | 服务端取消：断流减少了共享服务占用 |
| C | A 与 B 同时发生 |
| D | 输出 token、请求时长和服务波动 |

当前 DS 数据分不开这四条。旁观者 \(T_{\mathrm{e2e}}\) 变短也不等于服务端排队变短。它从到达计时，里面可以有 Runtime 等待、API 等待、生成和传输。

后续埋点使用概念分解，重叠时段不重复加总。拿不到的项标不可观测，不用残差冒充：

\[
T_{\mathrm{e2e}} = W_{\mathrm{runtime}} + W_{\mathrm{provider}} + T_{\mathrm{generation}} + T_{\mathrm{transfer}} + T_{\mathrm{other}}
\]

## 3. 近邻边界

以下判断依据公开摘要和版本页，不是逐页全文对照。全文审计放在阶段 D。

| 工作 | 已经做过 | 本文不能写成创新 |
| --- | --- | --- |
| Retire，arXiv:2610.01160 | 权限与 serving 资源分开；vLLM 上版本化执行、异步回收、KV 继承 | 「权限撤销不等于资源释放」；「取消后仍有回收过程」 |
| Vesta，arXiv:2610.14686 | 用 queueing externality 做放置，并报告吞吐与 TTFT | 排队外部性本身 |
| Readiness/Release，arXiv:2609.10964 | ready turn 何时进入 serving；workflow P95 | 又一个未加对照的 release policy |
| Stop Means Stop，arXiv:2607.14166 | 取消、暂停、超时是否挡住后续副作用 | 再证明一次撤权安全性 |
| Root-Scoped Quiescence，arXiv:2609.21284 | 撤权后异步委托路径的静默证明 | 「撤权后没有旧执行」 |

要保留的窄问题是：Runtime 先释放本地槽，而 serving 上的旧请求仍处在不同终止阶段时，这种时序如何改变独立工作流的等待和端到端；预登记模型能否预测这种影响。Retire 的重点是版本化执行、successor handoff 和 KV 继承。本文必须测量另一个对象，而不是把 Retire 的回收过程换一种说法。

| 维度 | 当前判断 |
| --- | --- |
| 问题是否真实 | 成立 |
| DS 黑盒实测 | 已有，尚未独立复现 |
| 后端机制证据 | 缺失 |
| 与 Retire 的区别 | 需要全文审计和 vLLM 对照 |
| 与 Vesta / Readiness 的区别 | 可论证，但必须写清处理组和事件链 |
| 新机制或新算法 | 不成立 |
| 测量型论文 | 有潜力，取决于本阶段四步 |

## 4. 阶段 A：审计已有 DS 确认性，不追加实验

第一优先级。汇总表不够写论文。审计写入 `docs/档案/v5.1/弃用-DS审计.md`，不改 `results/experiments/v5_0/ds/confirm/traces.jsonl`。

| 材料 | 要确认的问题 |
| --- | --- |
| 7000–7049 原始 JSONL | 每个 seed、每个臂是否完整 |
| 每条 trace 的 bystander | 是否为独立工作流，每 trace 的数量分布 |
| G0/G2 事件时间线 | 撤权、停读、放槽、旁观者启动的顺序 |
| API 元数据 | 模型标识、采样参数、max_tokens、实际输入输出 token、失败与重试、调用时间 |
| Bootstrap | 是否按 seed/trace 配对重采样，而不是把 8 个 bystander 当独立样本 |
| 协议 JSON | 本次运行是否使用冻结协议 |
| 分析输出 | P95 算法、缺失和异常值处理是否一致 |

另外核对三件事：请求配置是否真固定在记录里，而不只写在文档标题上；G0/G2 的先后是否平衡，限流或时段是否与臂相关；50 对是否真是 50 个独立配对单位。失败率、每 trace bystander 数和 P95 细节要补进审计，不能只留均值。

## 5. 阶段 B：独立时间窗口复现

审计通过后再跑。不把样本从 50 扩到 100 来追显著性。

- 同一模型、同一请求配置、同一工作流和处理组。
- 全新种子，与 6000–6014、7000–7049 隔离。
- 另一时间窗口里交错 G0/G2。
- 分析脚本在开跑前冻结。
- 复现批次单独报告，不先与 7000–7049 混合。

观察槽等待改善和端到端改善是否同向再现，高负载端到端相对值是否仍在 10% 门槛附近，以及对 token 数、失败和 API 时长是否敏感。先按目标效应量和区间精度决定样本量，再开跑。

## 6. 阶段 C：vLLM 小规模机制实验

先做兼容性，再决定是否做完整矩阵。核对所用 vLLM 版本的取消路径：异步引擎在任务取消或生成器关闭时是否进入 abort。2026-10 已有客户端断开后非流式请求未及时取消的社区报告；它不是本台架的证明，只说明断连不能默认等于 abort。

先只跑四组，脚本校准与 vLLM 验证分开报告：

| 组 | 客户端 | Runtime slot | 后端 |
| --- | --- | --- | --- |
| G0 | 继续读 | 保留到自然结束 | 自然完成 |
| G2-local | 断流 | 立即释放 | 记录实际取消行为 |
| G2-residual | 断流 | 立即释放 | 台架上观测或注入的残余；不能用脚本结果代替 |
| G2-hold-slot | 断流 | 延迟释放 | 用来隔离本地放槽本身 |

记录并分列：进入引擎、开始执行、发起 abort、abort 确认、离开 running、离开调度队列、可得的 KV/GPU/活跃请求指标，以及 successor 与 bystander 的入队、启动、完成。请求终止、出调度队列、资源指标变化是三种事件。只有实际观测到的级别才能写入对应结论。

## 7. 阶段 D：预登记模型与相关工作终审

现有 \(M_0:\widehat{\Delta T}=\alpha\Delta U_{\mathrm{client}}+\beta\) 太宽。自由的 \(\alpha,\beta\) 容易把现象拟合掉。开跑前写明：

- \(\Delta U_{\mathrm{client}}\) 是减少的本地槽占用，还是客户端消耗的服务量。
- \(\Delta T\) 是 bystander P95 的配对差，还是单请求差。
- \(\alpha,\beta\) 是否跨负载共享。
- 后端残余是否作为单独变量。
- 训练集与留出集没有信息泄漏。

至少比较三个模型，复杂度受约束。M2 拟合更好不等于新机制。要有留出预测，并报告相对 M0 的预测误差变化。

| 模型 | 解释 |
| --- | --- |
| M0 | 本地释放时间差 + 固定取消开销 |
| M1 | 本地释放时间差 + 可观测后端残余服务量 |
| M2 | 本地释放时间差 + 后端残余 + successor/bystander 调度交互 |

相关工作终审不做泛泛的 Agent Runtime 检索。检索交集是：in-flight cancellation、client disconnect、backend abort/reclamation、shared serving queue、independent-request tail latency。重点读 Retire 全文，看它是否已经测量旧请求资源回收对其他独立请求的影响。若指标和条件相同，创新空间收窄，改贡献句，不保留「首次」表述。

## 8. 论文定位判定

| 证据结果 | 论文定位 |
| --- | --- |
| DS 独立复现成功，vLLM 没有可重复机制结果 | 黑盒 API 测量型论文 |
| DS 复现成功，vLLM 显示本地释放与后端残余的关系，但效果可被 M0 解释 | 系统测量与边界分析 |
| DS 复现成功，vLLM 出现 M0 不能解释的稳定现象，且 M1/M2 留出预测成功 | 有限机制增量，可以尝试系统方向投稿 |
| Retire 或其他近邻已经覆盖同一对象和结论 | 缩小贡献并重新定位，不宣称新颖 |
| DS 不能复现，vLLM 也没有机制证据 | 不以当前主张发布 5.0 论文 |

第三行成立也不等于录用。它只说明贡献和实验依据比现在清楚。

## 9. 禁止

- 为了显著性继续加种子，而不先写效应量和区间精度。
- 把脚本残余写成 vLLM 的真实机制。
- 把高负载端到端的正差说成跨过了 10% 工程门槛。
- 把 D2 分叉没有出现写成 5.0 失败，或写成服务端立即停止。
- 修改 7000–7049 确认性 JSONL。

## 10. 执行结果（2026-11-04）

合同四步都做完了。对上第 8 节时，落在最后一行附近：DS 不能按预登记的双负载结果复现；本机 vLLM 有一次四组观测，但没有可重复、且 M0 解释不了的后端残余。定位是不以当前主张发布 5.0 论文。

| 步骤 | 结果 |
| --- | --- |
| A 审计 | 通过。封存 JSONL 未改。高负载端到端 8.6%，没有过 10% 门槛 |
| B 复现 | 种子 8100–8132。中负载两道门槛过，但区间半宽约 1.2 秒。高负载槽等待 −0.9%，端到端 0.2%，区间含 0 |

| D 模型与近邻 | M0 把中负载外推到高负载是过预测，不是新机制。M1/M2 未拟合。不写「首次」 |
