## 工作流

文件 `results/experiments/v1_3/workflow/runs.jsonl`，140 行。库存预订 20 种子 × A/B/C。先调用 `read_inventory` 再预订，以及先写计划再预订，各 20 种子 × A/C。变化在首个增量后 0.8 秒把库存打到 0。

| 工作流 | 臂 | n | 撤销前见到工具调用 | 有效提交 | 旧提交 | 重复副作用 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 库存预订 | A | 20 | 1 | 1 | 0 | 0 |
| 库存预订 | B | 20 | 2 | 0 | 0 | 0 |
| 库存预订 | C | 20 | 0 | 0 | 0 | 0 |
| 先比较再预订 | A | 20 | 20 | 0 | 0 | 0 |
| 先比较再预订 | C | 20 | 20 | 0 | 0 | 0 |
| 计划中途失效 | A | 20 | 17 | 0 | 0 | 0 |
| 计划中途失效 | C | 20 | 19 | 0 | 0 | 0 |

先比较再预订的 40 次都在撤销前调用了工具，随后预订被拒绝。库存已经是 0，网关不接受过期预订。库存预订大多还在写说明时就被撤销，所以撤销前的工具调用很少。`read_tool_seen` 会把运行时自己的刷新也算进去，上表不用它判断模型有没有读库存。

有几行任务状态是 `failed`，但 `error` 为空，也没有传输错误，更没有旧提交。

## 六项

1. 失效后的本地槽位：有害确认性里，C 相对 A 的撤销到释放在长任务上约 2.8 到 4.2 秒，中任务约 0.7 到 2.0 秒，短任务只有早时机约 0.5 秒。短任务的中、晚时机对不齐。
2. 相对普通断流的增量：三臂都触发的 74 对上，B 与 C 的槽位差 0.005 秒，文本差约 0.2 词元。增量不在断流速度。无害变化上 C 的误撤销是 0/180，B 是 146/180。
3. 队列等待依赖 FIFO。只有 FIFO 的 A−C 均值达到预先写下的 1 秒；中负载 FIFO 的区间整段高于 1 秒。SJF 没有达到。低负载 FIFO 的均值仍然高于 1 秒。
4. 恢复完成：短中长的 C 相对 A 分别是 +5、−5、−10 个百分点，点估计没有越过 10 个百分点的界限。长任务的区间包含更大的下降。
5. 副作用：确认性、队列、恢复和工作流里，旧 attempt 提交是 0，重复副作用是 0。0 只覆盖这些场景和那五类各 50 次的确定性顺序。
6. 收益边界：变化越早、生成越长，本地槽位差越大。短生成在 0.80 秒和 1.80 秒的时机上经常来不及触发。服务端是否停止生成或停止计费没有被观察到，`provider_abort_not_issued` 表示没有调用供应商取消 API。
