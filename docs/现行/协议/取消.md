# 取消

这些事件分开记录：

| 事件 | 含义 |
| --- | --- |
| `cancel_requested` | 已请求取消 |
| `eligibility_revoked` | 旧 token 失效 |
| `stop_signal_sent` | 已对真实进程调用 terminate 或 kill |
| `process_exited` | 进程已经退出 |
| `slot_released` | 有进程退出证据后才释放槽位 |

`results/runtime/chaos.json` 里的 `cancel_process` 是一次真实睡眠进程。它退出了，槽位释放了，`gpu_reclaimed` 是 false。

父进程退出而子进程还活着时，槽位保持未释放。测试 `test_grandchild_keeps_slot_until_it_exits` 覆盖这一点。

Linux 容器里另有一次两段信号。测试进程忽略 SIGTERM，之后仍能读到 pid；再发 SIGKILL，进程不在。记录在 `test_tool_user_cannot_write_workspace_and_term_then_kill_is_linux`。Windows 上的 `cancel_process` 仍是进程终止，不当这次 Linux 证明。
