# 仓库边界

日期：2026-11-10。这一步只把执行控制面收成可安装的包。研究模块仍留在原来的路径。

## 两个包

| 安装名 | 版本 | 导入名 | 职责 |
| --- | --- | --- | --- |
| `epochgate-runtime` | 0.1.0 | `epochgate_runtime` | RunLedger、fencing、副作用发布、崩溃对账、控制服务 |
| `epochgate` | 5.0.0 | `epochgate` | 已封存的研究运行时：准入实验、UCR、RRM、阶段 E/F |

`0.1.0` 是控制面第一次单独打包。Runtime 3.0 仍是工程线的名字，不是这个版本号的成熟度声明。

`import epochgate_runtime` 不加载 `epochgate`。`import epochgate` 不加载 `epochgate.runtime.Runtime`。研究类从 `epochgate.runtime` 导入。仓库命令 `epochgate runtime …` 和独立命令 `epochgate-runtime …` 调用同一组实现。研究子命令到执行时才导入研究模块。

权威代码：

```
packages/runtime/src/epochgate_runtime/
  ledger.py       RunLedger、阶段、fencing、事件
  service.py      本地控制服务
  files.py        锁内文件发布
  sandbox.py      容器发布
  sink.py         可控接收器
  recovery.py     崩溃对账
  scheduler.py    进程槽
  processes.py    取消和进程树
  worker.py       崩溃注入子进程
  f2p.py          评分解释
  cli.py          doctor、chaos、bench、inspect、verify、check
```

正确性测试在 `packages/runtime/tests/`。仓库根的 `uv run pytest` 仍只收集 `tests/`，那是研究测试。

```powershell
uv run pytest packages/runtime/tests -q
uv run epochgate-runtime doctor --out results/runtime/doctor.json
```

2026-11-10 这次控制面测试是 26 passed，27.01 秒。其中一项检查导入 `epochgate_runtime` 时研究包不在 `sys.modules`。

## 还没有做的事

研究线大约一万六千行仍在 `src/epochgate/`。薄转出口已收进 `legacy/出口/`。`legacy/archived-research/README.md` 只做索引，不搬代码。下面这份目录是目标，不是当前树：

packages/runtime/          已经是控制面

benchmarks/                现在仍是 packages/runtime/tests 和 results/runtime
research/archived/         现在仍是 src/epochgate 里的研究模块

下一步不要先搬那一万六千行。先关掉还开着的执行边界：

- 历史编码 Run `code-de85cb5530a6` 里三次 `eg_bash` 仍是 `INTENT_RECORDED`。当前插件在 `EG_CONTROL_URL` 存在时会调用启动和结束；`lock_workspace` 之后工具用户不能写 `/workspace`。容器启动默认仍把 `/workspace` 交给 uid 1000，调用方要自己锁。

- `packages/contracts/schemas/` 里的 `runtime.v1` 没有被 Python 或 TypeScript 读取。插件观测仍写 `eg2.events.v1`。
- `gpu_reclaimed=false` 在现有记录里表示这次测量没有观察到回收，字段本身容易被读成“已确认没有释放”。

`results/` 里已封存的实验数字没有因这次拆包改写。`results/runtime/doctor.json` 在拆包后重跑了一次，`package` 现为 `epochgate-runtime`，`package_version` 现为 `0.1.0`。
