# 接入 DSH

```powershell
uv run egctl init
uv run egctl serve
```

服务监听 `epochgate.yaml` 里的地址，默认 `127.0.0.1:8765`。它打印 base URL，并把 pid 写进 `.epochgate/server.json`。日志在 `.epochgate/logs/serve.log`。

另一个终端把 Agent 指到这个 URL。插件是 `packages/eg-workspace`，它只通过 HTTP 访问控制服务：

```powershell
$env:EG_CONTROL_URL = "http://127.0.0.1:8765"
$env:EG_REQUIRE_CONTROL = "1"
$env:EG_USE_EXISTING_CONTROL = "1"
uv run egctl demo --scenario coding --model deepseek-flash
```

`EG_REQUIRE_CONTROL=1` 时，控制服务不可达，写文件和容器命令直接失败。密钥留在宿主机进程里，不进入工具容器。

示例说明在 `examples/03-dsh-agent/` 和 `examples/04-coding-task/`。

在自己的 Python 进程里使用同一本账本：

```python
from epochgate_runtime import Runtime

runtime = Runtime.open(".epochgate/epochgate.db")
attempt = runtime.reserve(run_id="example-001", resource="workspace/main.py")
runtime.close()
```

`reserve` 只申请资格。文件是否发布仍由受控发布检查 token 和摘要。这个接口不接受调用方传入的 SQL，也不把发布用户的身份交给 Agent。
