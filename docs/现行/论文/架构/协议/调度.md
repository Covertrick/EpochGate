# 调度

`ProcessScheduler` 用真实子进程占据工具槽。容量和队列都满时，新 Run 被拒绝。进程退出后才释放租约。

W0 是这个调度器旁边的三种进程负载，不是 Agent 负载，也不是 GPU 负载。并发 2，每种重复 3 次，每个进程睡眠 0.05 秒。中位数：

| 配置 | 中位秒数 |
| --- | --- |
| B0，只有进程 | 0.077 |
| B1，建 Run 再起进程 | 0.078 |
| B2，提交到接收器再起进程 | 0.093 |

样本只有 3 个。这里不把 0.093 写成尾延迟结论。

同一睡眠在并发 1、2、4、8 上又各测了 3 次，原始数字在 `results/runtime/benchmarks/w0_scale.json`。并发 4 的中位是 B0 0.083 秒、B1 0.083 秒、B2 0.082 秒。并发 8 的中位是 B0 0.180 秒、B1 0.088 秒、B2 0.089 秒。这是本机进程。

`ClassScheduler` 按 run、model、tool 分开占槽。一类满了只拒绝这一类。W0 拉起进程时用的仍是 `ProcessScheduler` 的工具槽。
