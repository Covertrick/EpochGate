# 信任边界

宿主机运行 DSH Provider、实验控制器和插件服务。Agent 能碰到的文件、终端和测试在 Linux 容器里。DeepSeek 密钥只留在宿主机进程环境，由 `.env` 的 `DS_API_KEY` 映射为 `DEEPSEEK_API_KEY`。

## 谁可以看见什么

| 对象 | 宿主机 DSH | 容器内工具 | 评分进程 |
| --- | --- | --- | --- |
| API 密钥 | 可以 | 不可以 | 不可以 |
| 当前工作区 | 不直接改 | 可以改 | 只读评分副本 |
| gold patch、witness、标注 | 不可以 | 不可以 | 可以 |
| 未来 Git 对象 | 控制器单独持有 | 不可以 | 评分时按需读取 |
| `.env` | 可以 | 不可以 | 不可以 |

容器以非 root 运行。工作区可写。网络只开放任务声明需要的依赖安装；不能 `git push`。容器退出后删除该次进程和工作目录。

## 三层拦截

1. `tools/pre-execute` 决定允许、拒绝或审批。
2. `ctx.tools.guard()` 单调拒绝：宿主机路径、`.env`、gold 目录、`git push`、未登记工具。
3. 容器的用户、挂载和网络限制。命令字符串匹配不是安全边界。

默认 DSH profile 里如果还有能在宿主机执行任意命令的 Bash，研究 profile 必须去掉或把它指到容器 executor。研究插件自己的 repo-tools 是安全的，也不能留下另一条宿主机通道。

## 验收

未授权工具调用失败。Agent 读不到宿主机 `.env`。`git push` 失败。gold 路径打开失败。容器环境没有 `DS_API_KEY` 和 `DEEPSEEK_API_KEY`。容器内 `git log` 和对象库不含未来的参考修复。执行环境是 Linux，脚本和仓库文件保持 LF。

泄漏审计同时扫描 prompt、挂载、工具目录、环境变量、检索索引和容器能读到的 Git 对象。扫描范围写成 [audit_gold_leakage.py](../../../scripts/audit_gold_leakage.py)。

## Runtime 3.0

控制权威在 `epochgate_runtime.ledger.RunLedger`。插件里的路径拒绝和工具名拒绝是提前检查。文件能不能发布，仍由控制服务按当前 fencing token 决定。`eg_bash` 在控制服务可达时会记下启动和退出观察；它不发布工作区文件。`lock_workspace` 把 `/workspace` 交给 uid 1001，把 `/scratch` 交给 uid 1000。工具用户写不进工作区。

2026-11-10 的容器检查在 `packages/runtime/tests/test_security_boundary.py`，容器名 `eg-rt-boundary`，镜像 `python:3.10-slim`。启动参数包含 `--network none`、`--security-opt no-new-privileges`、`--memory 256m`、`--pids-limit 64`，没有挂载 docker socket。

| 检查 | 这次观察到的结果 |
| --- | --- |
| `docker inspect` | `Privileged` 为 false，`NetworkMode` 为 `none`，`Mounts` 长度为 0 |
| 工具用户看见的 `/var/run/docker.sock` | 不存在 |
| 暂存路径 `../kept.py` | 发布拒绝 |
| 暂存符号链接指向 `/etc/passwd` | 不发布，`/workspace/passwd.py` 不出现 |
| 读完暂存后再把文件改成另一份字节 | 写进工作区的是读入内存的那一份，文件属主 uid 1001 |

`results/runtime/read_race.json` 把替换和截断放在读完之后。容器发布端写出的是读入内存的那一份，SHA-256 仍是 `050d3aac3ac80d43bcadb8c6c34420ad6cef6d61a59b06141604e7c085e165fb`。宿主 `publish_file` 按路径改名，两次都停在 `OUTCOME_UNKNOWN`，落盘字节不等于被哈希的那一份。这没有覆盖读文件过程中被截断的内核窗口，也没有做内核级容器逃逸测试。信任基是宿主机 Windows、WSL 发行版 `eg-alpine`、其中的 Docker，以及容器镜像。发布用户能读暂存文件，是因为工具进程写出的文件对同容器其他用户可读。权限是 `0600` 时，发布会因读不到暂存而失败，不会改去读工作区里的其他文件。

控制服务是 RunLedger 的访问入口，不保存第二份授权。`EG_REQUIRE_CONTROL=1` 时，写文件和容器命令在控制服务不可达时直接失败。进程执行器启动工具前会从子进程环境删掉 `DEEPSEEK_API_KEY`、`EPOCHGATE_API_KEY` 和 `DS_API_KEY`。文件发布在账本锁内完成；资格已经撤销时，暂存文件不会换到工作区。这次 DSH 探针的结果文件里没有密钥。
