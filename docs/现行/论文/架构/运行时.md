# 执行控制架构

DSH 负责 Agent Loop、模型和 Session。EpochGate 负责 Run、提交资格、工具副作用、取消记录和恢复对账。可安装的控制面是 `epochgate-runtime` 0.1.0，代码在 `packages/runtime/src/epochgate_runtime/`。`ledger.py` 里的 `RunLedger` 是唯一权威。研究包 `epochgate` 不参与这条链。目录说明见 [repository-layout.md](仓库布局.md)。TypeScript 插件通过本地 HTTP 调用它，不另建数据库。

一条已经跑通的路径是：

1. `epochgate runtime doctor` 确认 Python、Node、DSH 和 Docker。
2. 控制服务创建 Run，并把 `EG_CONTROL_URL`、`EG_RUN_ID` 交给 DSH。
3. `eg_read` 只做准入。`eg_write` 再 `reserve`，把字节从 stdin 写到 `/scratch/.eg-staging/`。`path-guard.js` 和 `eg-policy` 只能提前拒绝，不能授权发布。
4. 控制服务在写事务里核对 fencing token 和 SHA-256。发布用户是容器内 uid 1001，把已经读入内存的字节写到 `/workspace`。工具用户 uid 1000 不能写这个目录。
5. 事件留下 `attempt_opened`、`intent_recorded`、`file_published`。`eg_bash` 再记 `command_started` 和 `command_exited`。看到退出码且 token 仍匹配时，观察记成 `RESULT_PERSISTED`。命令本身不发布工作区文件。
