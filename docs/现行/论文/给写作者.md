# 给写作者

这篇是实证测量，不是新算法论文。不要写「我们发明了 fencing」。要写：在这套真实模型和工具执行里，资格撤销、效果不确定和开销分别测到了什么。

## 三个问题

| 问题 | 回答用哪份材料 |
| --- | --- |
| RQ1 撤销 | [数据/01-主实验/主数字.md](数据/01-主实验/主数字.md) 的十个场景、三例直接提交，以及 DSH 两条会话 |

协调规则在 [协议.md](协议.md)。旧 token 只有在 `supersede` 或 `revoke` 处理之后才失效。只调用 `supersede(run)`、不推进 sink 时，新 token 也会被 `commit_authorized` 拒绝。这记为协调缺陷。DSH 的 `publish-file` 只核对 fencing token，不读 EffectSink 版本。

## DSH 会话怎么写

对齐的那条是 Run `dsh-963323c7fb0c`：读库存、第一次写入被拒、再读、用新 token 写下 `order 0`。没有通知的那条是 Run `dsh-452adcb9b31e`：库存已经改成 0，仍写下 `order 3`。

`EG_PUBLISH_GATE` 是实验停顿，插在 reserve 和 publish 之间。模型没有调用 `supersede`。通知是控制服务的 `POST /runs/{id}/supersede`。轨迹帧在 `数据/01-主实验/dsh轨迹/`，现场文件在 [dsh现场/aligned/order.txt](数据/01-主实验/dsh现场/aligned/order.txt)。汇总在 [dsh_revocation.json](数据/01-主实验/dsh_revocation.json)。
