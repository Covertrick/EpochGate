# 执行语义与保证边界

日期 2026-11-19。对象是当前工作区里的 `epochgate-runtime` 0.1.0 和 `scripts/reliability_contract.py`。不改 RunLedger、Claim、Publisher 的协议。`docs/开发文档/Runtime-正确性缺陷清单.md` 仍是 `7ac72dd` 的快照，不代表本文件。

研究问题是：在外部状态变化和执行故障下，运行时能安全提交什么、恢复什么，以及要有哪些证据才能把执行安全和任务进展分开。

## 七个对象

WorldState。外部真实业务状态。履约任务里是库存或审批文件。Coding 任务里是并发修改之后的工作区，不是模型读过的那一版。

ObservedState。Agent 已经读到的状态。Coding 以工具轨迹里的 `read_file` 为准，不从最终补丁反推。没有这次读取，就不说模型看见了并发修改。

AuthorityState。控制面已知的版本和资格。落在 `RunLedger` 的 `fencing_token` 和 `eligible`。`EffectSink` 另有自己的 `sink_epoch.version`。两处版本不是自动相等。

Attempt。创建时冻结的凭证和动作。包括当时的 fencing token 和 payload 摘要。凭证后来变旧，不改写这份冻结记录。

Claim。已获授权的提交决定。决定点是 `claim_publish` 把记录写入账本。`os.replace` 在这次写入之后，不在同一个 SQLite 事务里。

PhysicalEffect。接收端或文件系统实际发生的副作用。履约以目标文件字节为准。Coding 以接收端保存的补丁字节为准。隐藏测试是否通过是任务进展，不是物理效果本身。

Receipt。可核验的效果证据。缺失时不能代替 PhysicalEffect。有回执也不自动说明世界状态仍然有效。

## 六个术语

旧凭证。权威版本已经变化，冻结 token 不等于当前 token。只追加一行注释也会使凭证变旧。版本过期不等于语义不安全。

实际语义不安全。独立 Oracle 判定这份内容在新的世界状态下无效。Oracle 是隐藏测试或事先写明的业务检查，不是 token 比较。

合法后继。一份新凭证，加上一份在并发后的工作区上可应用、并通过隐藏测试的新修复。base 上的黄金补丁通过，不算后继合法解。机制后继把这份修复送进接收端，只证明控制面肯接纳。Agent 后继才涉及模型。

正确停止。没有合法效果可提交时拒绝，并且没有留下过期副作用。拒绝本身不是任务完成。

物理效果已发生。接收端或目标文件能核到对应字节。

UNKNOWN。当前证据不能区分效果是否发生。文件不存在不自动证明所有类型的效果都没发生。账本缺少 Receipt 也不证明物理效果不存在。

## 保守拒绝

源文件末尾追加 `# epochgate-concurrent workspace version 2` 时，B2 和 B3 拒绝旧凭证。这符合版本保护。内容未必失效。这一格记为保守拒绝，不记为避免错误发布。

## 九条保证边界

旧凭证拒绝。只在权威版本已经更新，而且检查和决定被放在同一次协调里。`commit_effect` 的 B2 先读 token，再调用 `SharedReceiver.accept`，两次调用之间没有跨进程锁。在这个边界被收紧并重新测试之前，不把 B2 说成跨进程原子提交。

Claim 线性化。只对受控账本里的协作式提交决定。不覆盖账本之外的写入。

重复接纳限制。只在具备幂等身份和持久接收端时。同键同载荷返回 replay，不第二次接纳。同键不同载荷在 `EffectSink.accept` 返回 `conflict` 且不替换已存 payload。脚本里的 `SharedReceiver` 同样返回 conflict。

恢复。只对已经记录 Claim、并且效果状态还能核验的情况。恢复重放 Claim 里的字节。B2 不写 Claim，因此没有这项恢复。不能据此说 B3 在所有列上都更可靠。

发布载荷完整性。只对冻结字节和受控发布对象。暂存被换成陌生字节时，不能用陌生字节完成 Claim。外部写入者仍可能在替换时覆盖目标。这是保留的风险，不是已修复的成绩。

通知缺失。不保证识别未知的状态变化。通知没有送达时，版本可能还没有推进，四臂都可能接纳同一份旧内容。

外部不协作写入。不提供通用覆盖保护。`test_external_writer_is_outside_the_publisher_lock` 只证明锁外写入仍在。

任意 HTTP exactly-once。不保证。

断电持久性、GPU 与 KV 回收。未验证。进程退出、SQLite 事务和文件替换可见性要分开写。取消回执不是 GPU 回收。
