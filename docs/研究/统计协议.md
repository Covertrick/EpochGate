# 统计协议

写于读取 Coding v4 确认结果之前。确认集一旦开始，不改本文件里的总体、假设和排除规则。

不把旧 E4、新 120 格、E9、M4、Coding v3 和 Coding v4 加进同一个成功率。历史 H5 的五对全同向只作为小样本机制观察：精确 McNemar 双侧 p=0.0625，区间宽。百分位 bootstrap 出现零宽度时，不把它当作精度。

## 两个总体

全分配任务。分母是冻结之后分配的全部任务—故障实例，包括没有形成补丁、触顶和无效故障。回答运行时加工具体工作流整体发生了什么。

已产生效果的条件子集。分母是真实生成并交付了可评分效果的任务。回答给定一个效果时，保护机制如何处理。

两个总体都报告。不能只留下模型成功提交的补丁，然后声称保护机制提高了任务成功率。

四臂若共享一份模型提案，评价层是 proposal-conditioned，不是四次独立生成。Agent 在拒绝之后重新读取并生成新补丁，单独记为端到端后继。两层不合成一个成功率。

## 三个主假设

H-A 提交边界。对照是 B1 对 B2，条件是通知已经送达。指标是过时凭证接纳的配对差。

H-B 恢复能力。对照是 B2 对 B3，接收端相同。指标是已授权效果的可验证恢复率。B2 没有 Claim 时，不把它的“不能恢复”写成全面失败。

H-C 进展代价。指标是安全拒绝之后最终合法完成的比例，加上误拒的描述性分解。误拒指 Oracle 认为内容仍然有效、却因旧版本被拒绝。

物理发布完整性留在确定性实验，不估计成总体概率。E12 的零结果保留，不新开诊断实验。

## 方法

过时接纳使用配对差、不一致对和精确 McNemar。隐藏测试通过按独立任务给比例和 Clopper–Pearson 区间。安全但未完成用终态转移计数，不合并成一个分数。合法后继按生成、接纳、隐藏测试三个阶段报告。效果恢复按故障和接收端分层。不必要拒绝使用独立语义 Oracle，不用 token 年龄代替。模型耗时按任务报告中位数、分布和超时。运行时成本只有与 E7/E8 相同配置时才比较。

六对不一致且全部同向时，双侧精确 McNemar 的 p 值是 0.03125。五对全同向是 0.0625。这不是把同一确定性场景重复到六对的理由。

## 样本

v4 确认集就是 `frozen-tasks.json` 里的六个任务。即使六格全部成功，也不写成跨项目结论。半宽仍不小于 0.25 就停，不加任务，不换任务。

开发集全部触顶或没有可评分补丁时，确认集不启动。失败格留在开发集分母里。

若确认结束后仍要做更宽的外推，必须另开协议，事先写明抽样规则和资源上限。本文件不授权那次扩展。

## 敏感性

每批能算的都要分开列出，不能相加：

- 全分配对已产生效果
- 按仓库
- 履约与 Coding
- 按通知状态
- 按语义变化类型
- 按接收端能力
- 按实验版本

精度不够就写描述性证据。成功标准是每条数字都有总体、分母、对照、单位、区间和适用范围。
