# v5.1 相关工作终审

日期：2026-11-04。检索交集限于 in-flight cancellation、client disconnect、backend abort/reclamation、shared serving queue、independent-request tail latency。全文来自 arXiv HTML/PDF，不是摘要转述。

## Retire，arXiv:2610.01160

《Serving a Revisable World》。vLLM 上的版本化执行：请求持有调度和内存，版本持有发布权限。ADVANCE 撤权，FENCE 关闭写者，ALIGN 认证可继承前缀，RESUME 启动后继，RECLAIM 异步回收。主指标是 revision-to-successor TTFT，中位相对 native abort + cold restart 降低 17.1%，并检查废弃输出是否发布、KV 是否按契约继承。

它测量了无关租户：TP=4 上替换租户 A 后，租户 B 的 KV digest 和 block ID 不变，B 的中位运行时间变化 1.0%，跨中断帧间隔变化 1.8%。这是隔离检查，不是「本地槽立即释放 vs 持槽到流结束」对独立工作流 P95 的配对实验。Retire 没有报告 bystander 槽等待，也没有把客户端断流后的未知服务端残余当成处理变量。

因此不能写「权限撤销不等于资源释放」或「取消后仍有回收」为本工作的创新。也不能写本工作是首次观察旧请求对其他请求的影响。可以保留的窄句是：在客户端可观察的 Runtime 槽上，比较继续读和立即停读放槽，对另一条独立工作流的槽等待和端到端；服务端处于哪一个终止阶段，DS 数据没有观测到。

## Vesta，arXiv:2610.14686

用队列外部性给额外 prefill/transfer 定价，并报告吞吐和 TTFT。排队外部性本身不能写成本文贡献。本文没有新的放置算法。

## Readiness/Release，arXiv:2609.10964

把 ready 和 release 分开，用 mean–CVaR 决定何时把 turn 提交进 serving，报告 workflow P95。本文的 G2-hold-slot 是放槽时序对照：脚本里能分开记时，本机 vLLM 四组里也跑了一次。那一次只说明本地多握 1.5 秒槽会把下一条请求推迟约 1.5 秒，不是又一个 release policy，也没有新的放置算法。

## Stop Means Stop，arXiv:2607.14166

测的是框架取消、暂停、超时之后副作用是否仍落地。本文不把撤权安全性再说一遍。

## Root-Scoped Quiescence，arXiv:2609.21284

证明的是撤权后旧授权路径的静默，不是旧 serving 请求对独立请求尾延迟的测量。

## 终审句

近邻没有用本文这组处理（G0 继续读并持槽，G2-local 停读并立即放槽）和这组指标（trace 内 bystander P95 的配对差）报告过 DeepSeek 黑盒结果。这不足以证明新机制。Retire 已经把旧执行的回收和后继 TTFT、无关租户隔离放在 vLLM 上测量。本机四组只看到本地握槽可以在 running 已经为 0 时挡住下一条请求，没有 abort 回执，也没有 KV 曲线。不能把这次观测写成另一个后端机制，也不能写「首次」。
