## 2. 冻结的问题与贡献边界

目标标题：**In-Flight Revocation Decisions for Agent Runtimes: Continue, Replan, or Commit under Uncertainty**。

只保留四个运行时对象：当前 attempt、状态谓词、剩余有效服务 \(S\)、重启/重规划服务 \(C\)。动作只有：

* `continue`：继续当前生成；
* `abort-and-replan`：停止本地读取、释放逻辑槽、创建新 plan；
* `accept-if-valid`：候选动作已经形成且 Gateway 的二次检查通过时提交。

定义 \(\Delta=\hat C-\hat S\)，误差带 \(m=\epsilon_C+\epsilon_S+\tau\)。决策规则：谓词无效时必须 `abort-and-replan`；候选已形成时只能进入 Gateway 检查；其余情况下，\(\Delta<-m\) 才切换，\(\Delta>m\) 才继续，\(|\Delta|\le m\) 进入 `continue/defer`，不得声称知道最优动作。

创新性只声明三点：误差带内的不可区分语义、状态谓词与成本差共同驱动的三态协议、以及 Gateway 在版本和谓词变化下保证 `stale accepted commit = 0`。不声明新队列定律、供应商 GPU 回收或全局最优。

## 3. 实验矩阵与数据量

### 3.1 离散回放（必须先完成）

每个 cell 使用 50 条配对 trace，固定种子 5000–5049；pilot 种子不得进入主表。主矩阵如下：

| 维度 | 水平 |
|---|---|
| 谓词状态 | valid / invalid |
| 负载 | low / medium / high |
| 槽数 | 2 / 4 / 8 |
| 事件时机 | early / mid / late |
| \(C/S\) | 0.5 / 0.75 / 1 / 1.25 / 2 |
| 估计误差 | 0 / 10% / 25% |
| 策略 | AlwaysContinue / AlwaysAbort / PredicateOnly / Oracle / UncertaintyAwarePolicy |
| 调度器 | FCFS / Runtime-PLAS / non-preemptive SRPT |

全因子组合过大，采用两层设计：

1. **确认性层**：4.0 的 2,400 行原样重放，再增加三态策略和误差水平；每个策略×状态×负载×时机×槽数×\(C/S\) cell 至少 50 条 trace。
2. **敏感性层**：对完整组合使用 30 条 trace/cell，记录原始 JSONL；只有通过确认性门槛的配置才进入最终论文表。

最低数据量按确认性层计算：状态 2 × 负载 3 × 时机 3 × 槽数 3 × \(C/S\) 5 × 误差 3 × 策略 5 × 调度器 3 × 50 = **60,750 条策略级 trace**。每条 trace 至少 36 个旁观者，因此最低旁观者观测数为 **2,187,000**。运行时闭环另行统计，不与离散回放行混合。

### 3.2 Runtime/Gateway 闭环

固定 Qwen2.5-1.5B-Instruct、fp16、`max_model_len=2048`、单卡 RTX 4060、vLLM 0.32.0。至少 3 个重复批次，每批 20 个任务，覆盖：谓词失效、谓词仍有效、候选已形成、版本竞争、取消回执四类；总计至少 **240 个 attempt**。每个 attempt 都保存完整状态字段、决策、估计误差、Gateway 检查、取消回执和最终资源状态。

## 4. 指标、统计和 Go/No-go 门

决策层指标：oracle action agreement、误中止率、误继续率、进入误差带比例、谓词失效后的切换延迟。系统层指标：失效服务量、重做服务量、总服务量、旁观者 P95/P99、当前 attempt 完成率、successor TTFT、旧提交数、重复副作用数。

所有配对结果以 trace 为重采样单位，bootstrap 10,000 次，报告均值、95% 区间和每格样本数。误差带内不得把某个动作标成错误；带外才计算 oracle agreement。

四道门：

* Gate 1 定义：三态语义、\(C,S,m\) 和 Gateway 条件可执行；否则只交 Runtime 设计报告。
* Gate 2 回放：误差带外接近 Oracle；误差带内不强行切换；stale commit=0；至少两个负载区间优于一个固定策略；否则停止扩展矩阵。
* Gate 3 闭环：三种动作都被真实状态变化触发，旧提交为 0，取消回执可追踪；否则只报告安全 Runtime。
* Gate 4 论文：代码、配置、版本、种子、原始日志、审计和限制齐全，且不把理想标签结果写成真实语义检测结果；通过后才准备 ArXiv。

## 6. 当前可行性判断

研究问题还在，论文现在不能发。带外动作标签与合成 Oracle 一致，这是估计公式的自洽，不是检测准确率。带内 24,300 次 defer 的旁观者等待和继续相同；有害前提下，不确定性策略比一直持槽短 1.15–2.44 秒，相对不到 6%，而且抽查的单条 W95 仍是 3.197 秒。240 个 attempt 证明 Gateway 会拒绝旧版本，没有证明服务端停止。近邻 Retire（arXiv:2610.01160）、Authority at Commit Time（arXiv:2609.31490）和 Cost-Aware Speculative Execution（arXiv:2606.07846）已经覆盖撤权重做、提交时拒绝和按成本取消。
