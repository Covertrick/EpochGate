## 留出评估

开发集 F1–F2 共 800 条，校准集 F3–F4 共 400 条，留出集 F5–F8 各 100 条。主分析的区间宽度倍数是 1。Cost Oracle 只看当前真实 \(C,S\) 和当前谓词。后悔是 \(J(\pi)-J(\text{Cost Oracle})\)，bootstrap 10,000 次。

| 族 | \(S\) 覆盖 | \(C\) 覆盖 | Full 后悔 | Point 后悔 | probe 率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| F5 更长参数 | 0.00 | 0.79 | 14.65 | 14.65 | 0 |
| F6 更大重规划 | 1.00 | 0.80 | 0.00 | 0.00 | 0 |
| F7 更晚谓词、更慢生成 | 1.00 | 1.00 | 4.24 | 4.24 | 0 |
| F8 没见过的工具 | 1.00 | 1.00 | 5.95 | 5.95 | 0 |

Full 和 Point 的逐条代价差是 0，区间下界也是 0。去掉 probe 的 Interval 与 Full 同样没有差别。过窄、校准、过宽三种宽度上的 probe 率都是 0。已生成 token 不超过 20 时，\(S\) 区间平均宽度 31.8 秒；超过 20 时是 31.1 秒，没有随信息明显变窄。CQR 把 \(C\) 的区间向外扩了 39.4 秒，所以留出样本几乎都重叠，分离规则很少触发。

校准集上的信息价值没有超过 probe 代价，策略因此一次都不 probe。这不是“probe 在不确定区域降低了后悔”，而是 probe 没有进入决策。

覆盖且分离、并且没有 probe 的样本上，Full 的动作和 Cost Oracle 一致，违反数是 0。F5 的 \(S\) 覆盖率是 0，这条选择命题盖不住留出集。每族有 33 条谓词已经无效的 trace，区间即便重叠也按谓词规则中止，这不是点估计在重叠区强行中止。

失败率硬约束在四族上都成立。F5 上 AlwaysContinue 的失败率是 1，因为完成期限按开发集的短服务冻结，留出的长服务超过了期限。Full 的失败率是 0.92，仍然不超过这条基线加 0.02。

## 运行时

vLLM 0.32.0、Qwen2.5-1.5B-Instruct、RTX 4060 上 240 个 attempt。这一层用场景区间触发动作，**不进入后悔主表**。

继续、中止、交给 Gateway 都出现了。30 次 probe 在读完预算后看到库存被降到 0，第二次决策改为中止。版本竞争的旧候选接受数是 0，谓词失效后的接受数是 0。60 次取消回执的等级是 `UNKNOWN`，`reclaimed` 为假。没有把 `num_requests_running` 写成 GPU 或 KV 已回收。

## 门

| 门 | 结果 |
| --- | --- |
| Gate A | 不通过。F5 的 \(S\) 覆盖率是 0，F5 和 F6 的 \(C\) 覆盖率低于 0.9，宽度也没有随 token 下降 |
| Gate B | 不通过。Full 的后悔没有低于 Point，probe 率为 0 |
| Gate C | 通过安全记录：旧提交 0，失效提交 0，回执保持未知 |
| Gate D | 不通过。五项里只有安全条件和失败率约束成立 |

因此现在能写的句子是：UCR-Agent 实现了安全的在途撤权状态机，但没有证明非 Oracle 的不确定性策略带来额外收益。
