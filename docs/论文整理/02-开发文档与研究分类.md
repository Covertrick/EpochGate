## 入口

### `docs/开发文档/README.md`

类：入口。处置：`BACKGROUND`。

它是找实验的目录，不是结果正文。表里把 E1–E12、M4–M6、Coding v2 到 v4c、Outbox 各自的协议、脚本、结果目录和“不重做”标了出来。研究问题写在文首。文末的否定句是现行口径：没有 GPU 回收，没有任意 HTTP exactly-once，没有掉电，没有跨任务普遍提升。

引用它来定位文件。数字回到它指向的那一份结果。

类：入口。处置：`SUPPORTING_EVIDENCE`。

由 `scripts/evidence_index.py` 从原始 JSON 生成。手改数字后再跑脚本会失败。它把旧 360、新 120、v3 的 2/4、v4 的 4/6 与 3/6、泄漏计数、Outbox 和 M6 的 p 值收成查找句。它不包含 v4c 的 4/6。v4c 以 `results/runtime/correctness/v4c-isolated/summary.json` 和 `结论范围.md` 为准。

## 研究定义

三份都在 `docs/研究/`。它们规定怎么说，不替代原始格子。

### `docs/研究/执行语义与保证边界.md`

类：研究定义。处置：`PRIMARY_EVIDENCE`。

写于 2026-11-19。对象是当时工作区的 `epochgate-runtime` 0.1.0 和 `scripts/reliability_contract.py`。定义七个对象：WorldState、ObservedState、AuthorityState、Attempt、Claim、PhysicalEffect、Receipt。定义六个术语：旧凭证、实际语义不安全、合法后继、正确停止、物理效果已发生、UNKNOWN。

九条边界里，论文正文需要守住的是：Claim 的决定点是账本写入，不是 `os.replace`；B2 的检查和接纳当时没有跨进程锁；通知缺失时四臂都可能接纳旧内容；外部写入不在锁内；掉电、GPU 回收和任意 HTTP exactly-once 未验证。末尾注释被拒绝，记为保守拒绝。

它明确写了缺陷清单仍是 `7ac72dd` 的快照。不要用这份语义文档把快照里的 D2“版本不落盘”说成当前代码。

### `docs/研究/统计协议.md`

类：研究定义。处置：`PRIMARY_EVIDENCE`。

写于读取 v4 确认结果之前。确认开始后不改总体、假设和排除规则。

两个总体：全部指派的任务—故障格；已经产生可评分效果的条件子集。四臂共享一份提案时，评价是 proposal-conditioned。三个假设：H-A 是通知送达时 B1 对 B2 的过期接纳；H-B 是同一接收端上 B2 对 B3 的恢复；H-C 是安全拒绝之后的合法完成，以及内容仍有效却被拒绝的误拒。

禁止把旧 E4、新 120、E9、M4、v3、v4 加进同一个成功率。五对全同向的双侧精确 McNemar 是 0.0625。六对全同向才是 0.03125，这不是把一个场景重跑到六对的理由。确认集六个任务即使全通过，也不是跨项目结论。半宽不小于 0.25 就停。

### `docs/研究/Novelty-and-Related-Work.md`

类：研究定义。处置：`PRIMARY_EVIDENCE`。

核对日期 2026-11-19。判决是联合测量，不包装成新框架。近邻是 Stale Does Not Mean Unsafe（arXiv:2609.29522）、Agentic Execution Assurance（doi:10.5281/zenodo.23119086）、From Evidence to Effect（arXiv:2609.08472）。页码沿用 `docs/现行/论文/相关工作.md`，那份冻结文件不改。

可以写的增量是同一次受控运行上的四列：旧凭证是否被拒、内容是否仍有效、合法后继是否完成、Claim 与物理字节是否一致或停在 UNKNOWN。v4 的通过数是固定失败反馈。Outbox 只在同库事务里比较。LangGraph 编码不进入迁移主张。

## 补实验

### `docs/开发文档/补实验协议.md`

类：补实验。处置：`PRIMARY_EVIDENCE`。

写于 E9、E10、E12 出结果之前。跑完不改首要指标。B0 没有决定点。B1 是资格检查返回允许，之后的撤销仍可能写入。B2 受限是先比较再放开再写。B2 强是同一次 `BEGIN IMMEDIATE` 里检查并写入，掉电原子性不在这项里。B3 的决定点是 `claim_publish`。

H1 看同一任务上终态相同而构成不同的配对数。H2 看通知送达时 B1 与 B2 强基线的过期接纳差。H3 看暂存被替换或截断后摘要不一致的次数。通知缺失时旧凭证仍被接受，事先写成边界，不算 H2 失败。脚本化格子方差为 0 时，确认批只取 1 个新实例。

### `docs/开发文档/补实验结果.md`

类：补实验。处置：`PRIMARY_EVIDENCE`。

第二批叫 Independent-instance deterministic replication。它不是总体效果估计。

E9：H1 的构成差是 22 对。H2 在通知送达时，B1 比 B2 强基线多 1 次过期接纳。通知缺失时 B2 强基线和 B3 仍接受冻结凭证。B2 的文件写不随 SQLite 回滚。不能说 Full 比一个已经原子提交的外部系统更可靠。Full 的三项消融都构造得出来：关掉版本验证则过期凭证被接受；关掉回执则文件在、回执空；关掉恢复则 Claim 停在 started、文件不在。

E10：H0 有 2 次物理字节与 Claim 不一致，H1 有 0 次。这两次是确定性反例。掉电未测。外部写入者先创建目标时，H0 和 H1 都覆盖了它。H2 容器没有与 H1 相同的崩溃钩子，那三格未测。

E12：主样本 35 格。D0 与 D1 的宏 F1 是 0，校准正确性是 1，因为只弃权。D1+ 与 D2 的证据校准正确性都是 0.914。按协议，校准没有提高，不写成新的诊断算法。
