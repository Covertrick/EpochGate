# Outline

This outline maps evidence. It is not the paper.

## RQ1

Does a terminal task state hide differences among safety, legal progress, and evidence?

Supported observation: in the 360-cell E4 recount, all three arms have 60/120 terminal successes, while full records 10 stale accepts and 50 legal successors.

Core data: `results/runtime/correctness/after/e4/cells`. Figure plan item 2.

Counterexample: the same terminal rate. The 120-cell repeat is a different fault mix and is not added.

Prior work: task success is already distinguished from effect evidence. Increment: the three columns were counted on the same cells.

Scope: exploratory model tasks. Likely objection: the batch was not preregistered.

## RQ2

What does each protection layer guarantee?

Supported observation: one admission does not include a second version check. Version check and claim recovery are different arms.

Core data: the same 360 cells, plus `docs/研究/执行语义与保证边界.md`. Figure plan items 1 and 3.

Counterexample: commit_only still accepts 60 stale effects.

Prior work: commit-time authorization and fencing tokens. Increment: the layers are measured side by side, not defined as a new protocol.

Scope: in-process lock for B2. Likely objection: B2 is not a cross-process fence.

## RQ3

How do claim, physical bytes, and receipt separate under faults?

Supported observation: the four process-kill points in the final regression distinguish not applied, applied, and unknown.

Core data: `results/runtime/correctness/final-regression/summary.json`. Figure plan item 5.

Counterexample: a missing receipt does not prove the bytes are absent. Power loss is unmeasured.

Prior work: crash recovery and receipts. Increment: the decision point is the claim row, and the replacement is reconciled by digest.

Scope: process kill, not power loss. Likely objection: Windows `TerminateProcess` is not power loss.

## RQ4

What safety, progress, and cost tradeoffs appear in a real tool workflow?

Supported observation: a stale token can reject a patch that still passes hidden tests. v4, v4b, and v4c keep separate denominators. v4 is fixed failure feedback. v4c is 4/6 and 4/6 on the same six tasks.

Core data: v4 confirm, v4b, v4b-historical, v4c. Figure plan items 4 and 6.

Counterexample: Outbox matches the version check on one database row. LangGraph coding remains a smoke test. E7/E8 cost is not the regression timing.

Prior work: stale-but-safe results. Increment: unnecessary rejection and legal successor are separate columns on the same run.

Scope: six confirmation tasks, one model, one image digest. Likely objection: the confirmation set is too small for a cross-project repair claim, and v4 leaked failure lines.
