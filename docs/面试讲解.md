# 面试讲解

讲这个仓库时，先讲测量问题，再讲系统不变量，最后讲结果的边界。不要把 G2 讲成一个新的最优取消算法。

## 一句话

EpochGate 把 Agent 的执行资格和 Runtime 槽位分开。我们测量的是：状态一变，不同的在途撤销政策会不会改变旁边那些无关工作流的等待。

## 一分钟

共享槽位上有一个长任务正在生成。外部库存中途变化。G0 把剩下的生成读完，到提交边界才拒绝。G1 看见信号就停，并立刻重做。G2 先问前提还在不在，只有前提为假才停并放槽。

因果实验跑在逻辑时钟上。同一种子的到达、服务时间和事件时刻相同，只改政策。4 个槽、早时机、前提已经失效时，G2 相对 G0 的旁观者 P95 等待在 12 个主格全部跨过预先写下的 10% 相对门槛，区间下界大于 0。放出的下一只槽全部交给后继任务，旁观者仍然少等，因为少占的是失效尾巴。

前提还成立时，结果会反转。restart 只有剩余服务的一半时，误撤反而让旁观者等得更少。restart 是剩余服务的两倍时，不误撤才更好。完成率没有差。槽位够多、队列消失时，等待差也消失。

## 五分钟

### 问题

文献里已经有过期计划拦截、服务端版本化撤销、程序级调度和重规划预算。缺的是同一条因果链：撤销政策、后继工作量、调度器，如何一起作用到**未受影响的旁观者**。

### 设计

Gateway 是唯一能提交的模块。调度器只看快照，不能调用环境和后端。流式取消是 `response.aclose()`，停的是客户端读。代码明确记下没有调用供应商取消接口。

主实验不用异步 Runtime 跑 50 乘以主格，因为那样控不住服务时间。回放器按同一条规则实现：过期 attempt 不能提交，同一个动作不扣两次。焦点任务固定 16 秒，事件在 20% 处，这样失效尾巴是 12.8 秒，可以和后继长度 \(\rho\) 乘 12.8 秒对齐。旁观者仍按 40/40/20 的短中长混合到达。到达在开跑前哈希，跑得快也不会把后面的到达提前。

三种调度器是对照，不是贡献：FCFS 把重规划放到队尾，SRPT 是已知剩余时间的 oracle，Runtime-PLAS 按工作流已完成服务降优先级。后一个规则来自 Agentix 的 PLAS，不是那篇系统的复现。

### 结果

有害主格 12/12 跨过门槛。中负载 FCFS、\(\rho=1\) 的差是 2.177 秒，相对 16.9%，区间 [1.731, 2.616]。无害 \(\rho=0.5\) 的差是 −0.735 秒，区间整段为负。\(\rho=1\) 的 50 条差都是 0。\(\rho=2\) 的差是 2.154 秒。

机制用一条 trace 讲，均值用 50 条。种子 5005 上，G2 在 3.2 秒把槽交给 successor，旁观者 P95 是 6.374 秒。G0 和“撤销了但继续占槽”都到 16 秒才放槽，P95 都是 11.163 秒。种子 5000 上三臂 P95 相同，所以要说明不是每一条 trace 都有差距。留一法没有让任何一格的均值跨过 0。

### 边界

完成率全是 1，因为观察窗足够长，这轮不能讲完成率。Runtime-PLAS 在无害路径上 7399 次派发都和 FCFS 顺序相同，那一列不是第二次独立复现。8 个槽时基线等待接近 0，绝对差约 0.01 秒。真实 API 的 60 条只核对事件链，两个任务是同时在飞的。

## 可能被问到的问题

**这和直接把请求取消有什么不同？**  
直接取消对应 G1。G2 多做的是前提判断。有害路径上，G1 和 G2 的放槽时刻一致，速度不是差别。差别在无害路径：G1 会制造 restart，G2 不会。restart 的长短决定旁观者变好还是变差。

**下一只槽给了后继，为什么还说旁观者受益？**  
因为 G0 除了同样要跑后继，还多占了失效尾巴。受益来自少占的那段时间，不来自“下一手的名字”。延迟释放把这段尾巴占回去之后，旁观者 P95 回到 G0。

**为什么不用真实模型估计 P95？**  
服务时间和到达要在政策之间配对。模型生成长度不稳定，会把处理效应和负载差异混在一起。真实调用只检查事件是否出现：撤销、本地停读、放槽、误撤、旧提交。种子 9104 的放槽比停读早 0.015 秒，所以不能说顺序每次都严格一样。

**调度器重要吗？**  
有害路径上三种调度的方向一致。没有做等效性检验，不能说调度完全没有影响。SRPT 知道剩余时间。PLAS 只在失效任务一直占槽的 G0 上改变过派发顺序。

**10% 是置信区间吗？**  
不是。10% 是点估计除以基线。区间只要求绝对差的下界大于 0。不能说“95% 区间证明至少改善 10%”。

**你证明了 GPU 省下来了吗？**  
没有。本地停读和槽位释放是客户端事实。供应商侧没有取消回执，用量记为未知。

## 不要说的话

- G2 在所有负载和调度器上更优。
- 我们发现了撤销策略的通用最优阈值。
- 这是首次提出撤销、队列外部性或前提感知。Vesta 已经用 queueing externality 描述放置决策。
- v1.8 的“后续任务首次等待”就是这次的旁观者 P95。
- 60 条 API 调用验证了 P95。
