## 1. 冻结的论文身份

### 1.1 核心研究问题

当外部状态变化到达时，对在途 Agent attempt 采取 **只在动作边界拦截（G0）**、**任何相关信号都提前撤销（G1）** 或 **仅当前提被破坏才撤销并释放 Runtime slot（G2）**，会怎样改变共享有限 Runtime slot 下 **独立旁观工作流** 的等待、尾延迟和完成情况？该影响如何被 **调度策略、负载、必要 successor 成本 \(\rho_h\)、错误重启成本 \(\rho_b\) 以及无害信号比例 \(p_b\)** 调制？

### 1.2 三项贡献（都还没有被 v2.0 证明）

1. **定义并测量 Bystander Queue Effect。** 把不受该次状态变化影响、也不属于目标 successor 的工作流单独作为评价对象。
2. **分开两条因果路径。** G2−G0 测提前释放失效执行的收益；G2−G1 测避免过度撤销、少注入无谓 successor 的收益。
3. **建立适用边界。** 收益如何随 FCFS / Runtime-PLAS / SRPT、负载和 \(\rho_h,\rho_b,p_b\) 变化；允许收益消失或变成尾部饥饿。

### 1.3 明确不主张

| 不写 | 原因 |
| --- | --- |
| 首次提出 Agent 撤销 / 在途撤销 | Retire、Stop Means Stop、框架 cancel API 已有 |
| 首次释放共享推理资源 | vLLM 抢占、Retire RECLAIM 已有 |
| 首次研究队列外部性 | Vesta 已把 queueing externality 用于放置 |
| 首次提出前提感知机制 | PlanFence / ATR 已覆盖依赖或决策条件 |
| 首次研究 Agent 工作流尾延迟 | Agentix、Readiness/Release 已报 P95/P99 |
| 首次关注重规划成本 | BRACE 已量化重规划 token 与尾延迟 |
| Provider GPU / KV / 计费已回收 | 当前只有 `response.aclose()` 与 `provider_abort_not_issued` |
| 完整复现 PlanFence / Agentix / Retire | 只做 inspired 基线 |

安全表述（投稿用）：

> To our knowledge, existing work has not systematically characterized how state-triggered in-flight revocation policies affect unaffected Agent workflows under shared bounded runtime capacity, particularly across workflow scheduling policies and successor-work costs.

### 1.4 推荐标题

**主标题：** Selective In-Flight Revocation Under Contention: Measuring Bystander Queue Effects in Stateful Agent Runtimes

备选（仅当 Panel B 出现稳定负效应时再考虑）：Bystander Costs of Over-Revocation: When State-Triggered In-Flight Abort Helps and When It Hurts

不使用 Premise-Aware Attempt Revocation 作为主标题。

## 3. 对象、政策与两条机制

### 3.1 一次撤销影响三类工作流

每条到达必须带 `workflow_id`。一次外生事件打上 `event_id` 后，运行中每条工作流只能落在下面三类之一；禁止把“后面排队的任务”统称后续任务。

| 角色 `workflow_role` | 定义 | 主文怎么用 |
| --- | --- | --- |
| `target` | 本次状态变化针对的原工作流，其当前 attempt 可能失效 | 解释 slot 占用与撤销时机，不是主指标 |
| `successor` | 同一 `workflow_id` 在撤销或动作拒绝后的新 attempt | 核算必要工作或错误重启，不是旁观者 |
| `bystander` | 不受该 `event_id` 影响、不需要因此重规划、与 target/successor 争用同一组 Runtime slot | **主评价对象** |

判定规则（写入协议，不允许事后改口）：

1. 若工作流的绑定前提依赖该事件改写的 `source_id`，且事件后 `premise_holds is False`，则该工作流是本次事件的 target；其之后创建的 attempt 是 successor。
2. 若依赖同一 `source_id` 但事件后前提仍成立，该工作流对本次事件既不是 target 也不是 bystander 的“受益对象”——在 G1 下它可能被误撤，记为 `false_target`，其重启记 `restart`。统计时 `false_target` **并入过度撤销分析，不并入 bystander**。
3. 其余共享 slot 的独立工作流记 `bystander`。
4. 一条工作流可以对事件 E1 是 bystander，对事件 E2 是 target。指标按事件窗口切片，再按 trace 聚合。

v2.1 主实验每个 trace 只放 **一次** 被分析的焦点事件（可另有填充事件，但不进入 \(\Delta\) 计算）。这样角色不会在同一估计里翻转。

### 3.2 G0 / G1 / G2 行为合同

三组共用：同一 Gateway、同一 `action_id` 去重、同一到达序列、同一状态事件时刻、同一副作用合同、同一成功判定。只改变：是否提前停本地读、何时放 slot、误撤后是否产生 restart。

| 组 | 现有代码近似 | 行为 | 禁止写成 |
| --- | --- | --- | --- |
| **G0** Boundary-only | v2.0 臂 A：`signal_policy=premise`，`stop_on_cancel=False` | 在途继续读、继续占 slot。dirty 时仍做 `check`。前提失败则 `eligibility_revoked`，但本地读跑完。提交点 Gateway 拒绝过期动作。之后才允许 successor | PlanFence 复现 |
| **G1** Any-signal abort | 臂 B：`signal_policy=any_signal`，`stop_on_cancel=True` | 相关来源出现任何新信号（含无害标注）即撤销资格、停本地读、立即放 slot；随后 restart/successor | “脏了就停”的最优策略 |
| **G2** Premise-selective abort | 臂 C：`signal_policy=premise`，`stop_on_cancel=True` | 仅 `premise_holds is False` 才撤销、停读、立即放 slot | 新算法；服务端已停止 |

补充合同：

- G0 的资格撤销仍发生，所以安全性不归因于停读。这与 v2.0 F5 一致。
- G1 在无害信号上 **必须** 产生 `false_cancel` 与 restart（除非原 attempt 已在信号前结束，记 `trigger_late` / `trigger_not_fired`，不得标成功撤销）。
- G2 在无害信号上 **不得** 撤销。v1.7 的 0/180 是行为验收，不是旁观者结论。
- 三组 `max_inflight` 相同。默认确认性用 **4** 个 Runtime slot（与 `FakeBackend` 默认一致）。Pilot 若 4 槽无排队，只允许把槽改成 2，改前写进协议，不得事后调。
- Provider 取消：继续 `provider_abort_not_issued=True`。论文只写 Runtime execution slots。

G0 可写 `PlanFence-inspired boundary gate`，前提是：提交前调用 `environment.check`，过期动作不能 commit。不要声称 derivation currency、精确依赖前沿或分布式 owner 查询。

### 3.3 机制 A 与机制 B 必须分开测

**机制 A：提前释放失效执行（有害变化，G2 vs G0）**

库存等前提被破坏。两边最终都需要 successor。successor 不是 G2 相对 G0 的新增工作，而是更早或更晚安排的必要工作。

\[
\rho_h = \frac{S_{\mathrm{successor}}}{R_{\mathrm{obsolete}}}
\]

- \(S_{\mathrm{successor}}\)：纠正后 successor 的服务量（回放器里写入，单位秒）。
- \(R_{\mathrm{obsolete}}\)：若走 G0，失效 attempt 从焦点事件到其自然结束还会占用的剩余服务量。

\(\rho_h\) 小：提前停读能腾出明显的失效占用。\(\rho_h\) 大：successor 很快把槽占回去，旁观者收益应缩小。

**机制 B：避免过度撤销（无害变化，G2 vs G1）**

前提仍成立。G2 继续原 attempt。G1 停掉仍有用的生成，再注入 restart。

\[
\rho_b = \frac{S_{\mathrm{restart}}}{R_{\mathrm{useful}}}
\]

- \(S_{\mathrm{restart}}\)：误撤后的替代 attempt 服务量。
- \(R_{\mathrm{useful}}\)：原 attempt 若不被停，从信号到完成的剩余有用服务量。

\[
p_b = \frac{\text{predicate-preserving signals in the analyzed window}}{\text{all analyzed signals}}
\]

主实验焦点事件要么有害（\(p_b=0\)，估 \(\rho_h\)），要么无害（\(p_b=1\)，估 \(\rho_b\)）。混合 \(p_b\in\{0.25,0.50,0.75\}\) 只在补充格子里做，用于说明 G1/G2 差异随无害比例出现。禁止把有害、无害的 successor 加在同一个 \(\rho\) 横轴上。

## 4. 调度器合同（不是 EpochGate 的新算法）

新主矩阵只保留三套。v1.8 的类别长度 SJF 留在历史节，不与 SRPT 并列。不加 EDF、MLFQ、ATLAS。

| 策略 | 代码名 | 排序键 | 角色 |
| --- | --- | --- | --- |
| FCFS | 扩展现有 `FifoAdmissionScheduler(order="fifo", replan_to_tail=True)` | 队列时刻；successor/restart 入队尾 | 与 v1.8 衔接 |
| Runtime-PLAS | 新类 `RuntimePlasScheduler` | 该 **workflow_id** 已完成的模型服务时间之和；相同则 FCFS。等待超过 `aging_s=25s` 的工作流提到队首 | Agentix PLAS 的 Runtime 级 inspired 基线 |
| SRPT | 新类 `SrptAdmissionScheduler` | 回放器写入的剩余服务时间（clairvoyant）。aging 同 25s | 理想短任务优先上界，论文中必须标 oracle |

共同规则：

1. 只在 `free_slots>0` 时派发队首就绪 attempt。
2. 资格撤销与 Gateway 不在调度器里实现；调度器只决定下一个占槽的是谁，以及是否对已 inflight 且合同要求取消的 attempt 发 `cancel`。
3. Runtime-PLAS **不是** Agentix 复现：它看不到引擎内 token 级抢占，只在 Runtime slot 粒度抢占/派发。论文写 `Runtime-PLAS-inspired`。
4. SRPT 的剩余时间来自 trace 字段 `remaining_service_s`，禁止用事后实际生成长度回填后再假装在线可知。
5. 调度器源码仍不得 import gateway / environment / backend 实现，也不得写具体工具名。

## 5. 指标与统计（先冻结再跑）

### 5.1 主指标（两个）

对每条独立 trace \(k\)、每个政策 \(g\)，只在该 trace 的 bystander 集合 \(B_k\) 上计算：

\[
W_{95}^{B}(g,k)=P_{95}\{t_{\mathrm{start}}-t_{\mathrm{arrival}}\mid \text{bystander in }k\}
\]

\[
F_{95}^{B}(g,k)=P_{95}\{t_{\mathrm{finish}}-t_{\mathrm{arrival}}\mid \text{bystander in }k\}
\]

`t_start` = 该工作流 **首次** `slot_acquired`。若观测窗结束仍未获得槽，等待记为窗长（右删失），并在表中单列 `censored_wait_count`。

`t_finish` = 有效提交成功时刻。未完成记删失，不把失败当成 0 等待。

配对效应（trace 内配对，再对 trace 做 bootstrap）：

\[
\Delta W_{95}^{\mathrm{early}}(k)=W_{95}^{B}(\mathrm{G0},k)-W_{95}^{B}(\mathrm{G2},k)
\]

\[
\Delta W_{95}^{\mathrm{selective}}(k)=W_{95}^{B}(\mathrm{G1},k)-W_{95}^{B}(\mathrm{G2},k)
\]

正值表示 G2 相对该基线缩短了旁观者 P95 等待。\(\Delta F_{95}\) 同构。主文同时报 \(\Delta W\) 与 \(\Delta F\)：只改善开始、不改善完成，必须写出来。

确认性事先写下的 **工程可辨认门槛**（pilot 后若方差过大只允许改门槛，并在协议补丁里留痕，不得改完再看数）：

- 中高负载、有害、FCFS：\(\Delta W_{95}^{\mathrm{early}}\) 均值 \(\ge 1.0\) 秒，才允许把“提前撤销有旁观者等待收益”写成主句。
- 无害、\(p_b=1\)、FCFS：\(\Delta W_{95}^{\mathrm{selective}}\) 均值 \(\ge 1.0\) 秒，才允许把“过度撤销损害旁观者”写成主句。
- 未达门槛就写“未达到预先门槛”，允许报点估计和区间。

### 5.2 次要指标（每条 trace 都要有）

| 字段 | 用途 |
| --- | --- |
| `bystander_completion_rate` | 防平均等待变好、完成变差 |
| `effective_workflow_throughput` | 观测窗内有效完成的唯一 `workflow_id` 数 / 窗长 |
| `target_recovery_success` | 目标最终是否有一次有效提交且旧 attempt 未提交 |
| `successor_service_s` / `restart_service_s` | 必要工作 vs 错误重启 |
| `false_restart_count` | G1 无害路径 |
| `reclaimed_slot_s` | 事件后到 G0 自然结束之间，G2/G1 提前释放的槽秒 |
| `slot_reacquired_by` | `bystander` / `successor` / `restart` / `idle` / `other` |
| `starvation_count` | 旁观者等待 \(>25\) s，或被后来者超越超过 2 次 |

目标 attempt 的文本词元差、撤销到放槽秒数，只作机制附录。不进 Abstract。

### 5.3 统计合同

1. 基本单元是 **workload trace（seed）**，不是 trace 里的每个任务。
2. 同一 seed 的 G0/G1/G2 × 三调度器回放 **同一** 到达时刻、同一焦点事件时刻、同一服务量向量（open-loop）。完成快的组不得提前注入下一批到达。
3. Bootstrap：对 trace 重采样 10000 次，报 2.5% 与 97.5%。种子写入协议。不是 Holm，不把区间写成显著性星号。
4. P95 要求：每条 trace 至少 **32** 个旁观者；确认性至少 **30** 条独立 trace / 主格。P99 不进主结论。
5. 排除规则预先写死：`runtime_failed`、回放器断言失败整条 trace 作废；`trigger_not_fired` 不进入条件效应，但留在整体意向分析。不得因为某一格好看加跑。
6. 完成率的观测窗 = 最后一条到达之后再加 `drain_s`。Pilot 后冻结 `drain_s`，建议初值 = 该 trace 最长工作流服务时间的 4 倍。

## 6. 实验包（小，有因果）

### 6.1 E1 政策对照

每个调度器、每条 trace 都跑 G0/G1/G2。这是所有图的底。

验收：同一 seed 三组的到达 JSON 哈希相同、焦点事件时刻相同、Gateway 拒绝原因集合可复述；唯一系统性差异是撤销与放槽时间线。

### 6.2 E2 延迟放槽（仅确定性回放，可选但建议做）

| 组 | 本地读 | Runtime slot |
| --- | --- | --- |
| G2 | 停 | 立即释放 |
| G2-delayed-release | 停 | 等到该 attempt 的原定服务终点再释放 |

只在 FCFS、中负载、有害、\(\rho_h=0.5\) 的一个格子做。若 G2-delayed 的 \(\Delta W_{95}^{\mathrm{early}}\) 相对 G0 接近 0，而立即释放的 G2 明显为正，才能把收益写到 slot 再分配上。不做 E2 时，论文必须把 G2 写成“停读并立即归还 slot”的组合处理。

实现：Runtime 增加 `slot_release_mode=immediate|delayed`。delayed 只挡 `max_inflight` 计数，不得让旧 attempt 再提交。

### 8.2 JSONL 必填字段（v2.1 schema）

每条工作流行：`trace_id`、`seed`、`policy`（G0/G1/G2）、`scheduler`、`workflow_id`、`attempt_id`、`workflow_role`、`parent_workflow_id`、`event_id`、`trigger_class`（`harmful`/`harmless`/`none`）、`premise_before`、`premise_after`、`arrival_mono`、`slot_acquired_mono`、`eligibility_revoked_mono`、`local_read_stopped_mono`、`slot_released_mono`、`slot_reacquired_by`、`service_s`、`remaining_service_s_at_event`、`successor_service_s`、`rho_h` 或 `rho_b`、`p_b`、`committed`、`old_attempt_committed`、`duplicate_side_effects`、`false_cancel`、`code_version`、`protocol_hash`。

时间一律 `time.monotonic()` 或回放逻辑时钟，二者不可混加。回放器只用逻辑时钟。

### 8.3 回放器语义（可行性的核心）

用逻辑时间推进，不 sleep。每个 attempt 有写入的 `service_s`。G0 有害：事件后继续占用 \(R_{\mathrm{obsolete}}\)，然后 successor 占用 \(S_{\mathrm{successor}}=\rho_h\cdot R_{\mathrm{obsolete}}\)。G2 有害：事件后立即放槽，successor 按调度器争夺槽，服务量同样是 \(S_{\mathrm{successor}}\)。G1 无害：事件后立即放槽，restart 服务量 \(S_{\mathrm{restart}}=\rho_b\cdot R_{\mathrm{useful}}\)。G2 无害：不停，打完剩余 \(R_{\mathrm{useful}}\)。

这把 \(\rho\) 变成受控因子，而不是从抖动的 LLM 长度里事后估计。真实 API 只验证事件顺序，不估计 \(\rho\)。

### 8.4 验收测试（pytest，无外网）

1. 同一 trace 三政策到达哈希相等。
2. 无害 + G2：`false_cancel=0`；无害 + G1：每个仍 inflight 的 false_target 都有 restart。
3. 有害三组：`old_attempt_committed=0`。
4. G2 立即释放后，若有等待旁观者且 successor 被 `replan_to_tail` 放到队尾，下一个 `slot_acquired` 的角色是 bystander（FCFS 合同）。
5. Runtime-PLAS：已消耗服务更多的长工作流，其后续 attempt 排在短工作流之后（除非 aging）。
6. SRPT：剩余服务更短的先派发。
7. Open-loop：即使 G2 更早完成，下一条到达时刻与 G0 相同。

## 10. Go / No-Go

### 10.1 可写 arXiv 测量预印本

- [ ] G0/G1/G2 同门闩、同 trace
- [ ] 三角色可从 JSONL 重建
- [ ] `slot_reacquired_by` 有数
- [ ] FCFS + Runtime-PLAS 都跑完（SRPT 作为 oracle 强烈建议，缺了要在限制里写）
- [ ] \(\rho_h\) 与 \(\rho_b\) 分面板
- [ ] 按 trace 配对区间
- [ ] 至少一次真实流式机制验证，或书面记录为何缺失
- [ ] 原始 JSONL、协议哈希、分析脚本可复跑

### 10.2 三种结果怎么写（预先承认都算完成，不是失败）

**结果 A。** FCFS、低 \(\rho_h\)、高负载：\(\Delta W_{95}^{\mathrm{early}}\) 过 1 秒门槛；高 \(\rho_h\) 缩小；无害上 G1 因 restart 使 \(\Delta W_{95}^{\mathrm{selective}}>0\)。主文写边界，不写 G2 处处最优。

**结果 B。** FCFS 过门槛，Runtime-PLAS 下 \(\Delta W\) 接近 0。主文写：程序感知调度已消化部分 HOL，语义撤销的**队列增量**变小，但无害路径上仍可能减少无谓 restart。这是有信息量的测量结论。

**结果 C。** 三调度下旁观者 \(\Delta W\) 都过不了门槛。先查：slot 是否被 successor 立刻接走、负载是否没进排队、服务时间是否太短。若合同无误，改写成负结果：在给定容量与服务分布下，提前撤销节省了目标占用，却没有稳定的旁观者增量。适用范围必须写死（slot 数、到达率、\(\rho\)）。**禁止**据此宣布“状态触发撤销无研究价值”。

### 10.3 会议投稿额外风险（不挡 arXiv）

审稿人会问：与普通取消抢占有何不同（用机制 B 与 \(p_b\) 回答）；为何 PLAS 不够（用结果 A/B 回答）；是否模拟器假象（用真实事件顺序验证回答）；是否只是把工作从 A 挪到 successor（用 `slot_reacquired_by` 与 \(\rho_h\) 回答）；完成率/饥饿（次要指标必须出表）。

没有 GPU 可以做 Runtime 测量；不能声称 Serving 层节省。
