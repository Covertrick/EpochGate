## 1. 要证明的假设

要检验的假设是：

> 当一个正在生成的 attempt 因外部状态变化而失效时，不同撤销策略会改变共享 Runtime 执行槽的占用；这种占用变化经过后继重规划负载和调度策略，改变其他独立工作流的等待时间与完成情况。

这句话拆成四个研究问题。论文主指标全部落在旁观工作流上。目标任务变快、successor 变快，都不能单独当成系统收益。

| 研究问题 | 要回答 | 主对照 | 成立时可以写的句子 | 不成立时必须写的句子 |
| --- | --- | --- | --- | --- |
| **RQ1** 提前撤销是否有用 | 失效 attempt 继续占槽，会不会让旁观者等得更久、完成得更差 | 有害变化上 **G2 − G0** | 在写明的负载、调度和 \(\rho_h\) 下，提前释放失效执行缩短了旁观者等待或完成时间 | 提前撤销减少了目标占用，但没有稳定改善旁观者 |
| **RQ2** 选择性是否重要 | 把仍然有效的 attempt 停掉，会不会注入多余 restart，从而伤害旁观者 | 无害变化上 **G2 − G1** | 只在前提失败时撤销，避免了无谓 restart 对旁观者的额外排队 | 误撤产生了 restart，但在所测负载下没有传到旁观者 |
| **RQ3** 调度是否改变收益 | 同一撤销政策的旁观者效应是否随调度器变化 | **调度器 × 政策** | 撤销的旁观者增量在 FCFS、SRPT、Runtime-PLAS 上大小不同 | 三种调度器上的配对差方向和量级一致，调度不是调节因子 |
| **RQ4** 重规划成本是否改变收益 | successor 或 restart 相对剩余服务有多大时，收益消失或反转 | **\(\rho\) × 政策** | 给出收益消失或反转的 \(\rho\) 区间 | 在 0.5、1、2 三档上效应方向不变 |

G0、G1、G2 的定义：

| 组 | 行为 |
| --- | --- |
| **G0** | 不提前停读，不提前放槽。动作边界检查，失效提交由 Gateway 拒绝，然后才允许 successor |
| **G1** | 任何相关状态信号都撤销在途 attempt，停本地读并立即放槽；若原工作仍需完成，产生 successor 或 restart |
| **G2** | 只有执行前提变为假才提前撤销、停读并立即放槽 |

RQ2 是相对 v2.0 最直接的增量：速度差已经测过，缺的是“少制造的 successor 有没有占用别人的槽”。

### 1.1 创新点怎样才算被这组实验确认

创新点不是“取消能释放资源”。确认标准是下面这条测量主张能否被数据支撑：

> 状态触发的在途撤销政策，会通过释放失效槽、以及避免把仍有效的生成换成 restart，改变共享有限 Runtime slot 下独立旁观工作流的等待和完成；该效应随调度策略和 successor 成本变化。

| 证据 | 对创新点的含义 |
| --- | --- |
| RQ1 在至少一个预先指定的主条件下达到工程门槛，且操作检验通过 | 可以主张“提前撤销有旁观者收益”，并必须同时报告它消失的条件 |
| RQ2 达到工程门槛 | 可以主张“选择性不是正确性装饰，而是少注入排队负载” |
| RQ1 与 RQ2 都未达门槛，但机制日志显示槽确实被 successor 接走 | 主张收窄为：释放了槽，但接收者是后继自己，旁观者外部性不成立 |
| RQ3 或 RQ4 出现交叉 | 这是论文的系统发现：收益有边界 |
| 四个 RQ 的旁观者效应都接近 0，操作检验却通过 | 可写负结果测量文。负结果要带适用范围，不能写成“方向没有价值” |
| 操作检验失败（有害时 G1 与 G2 行为不同，或无害时 G2 仍误撤） | **停止解释队列数字**。先修政策实现 |

相关工作边界保持不变，投稿句仍是：

> To our knowledge, existing work has not systematically characterized how state-triggered in-flight revocation policies affect unaffected Agent workflows under shared bounded runtime capacity, particularly across workflow scheduling policies and successor-work costs.

不写：首次提出撤销、首次释放共享资源、首次研究队列外部性、首次提出前提感知、Provider GPU 已回收、复现了 PlanFence / Agentix / Retire。

## 2. 因果归因合同

发现 G2 的旁观者 P95 比 G0 低，不能直接写成“语义撤销改善了队列”。还可能是任务更短、到达更疏、服务时间更稳、调度实现不同、失败样本被删掉。下面的合同用来排除这些解释。

### 2.1 配对

同一个 `workload_seed` 跑三次（或乘上调度器次数）。三次共享同一份：

- 工作流到达时刻
- 初始任务集合与长度分布
- 焦点事件时刻
- 目标剩余服务时间
- successor / restart 的预设服务时间
- 旁观者服务时间
- Runtime slot 数
- 调度算法
- Gateway 规则与 `action_id` 去重

唯一允许变化的是撤销政策。到达序列在运行开始前生成并哈希。G0 完成得更快，不得提前注入下一条到达。这是 open-loop 配对，不是三组各自重抽任务再比均值。

### 2.2 确定性回放先于真实 API

队列因果只用离散事件回放：

- 逻辑时钟，不 `sleep`，不调用 DeepSeek
- 服务需求、到达、失效时刻都写在 trace 里
- 每次派发、释放、撤销、再获取都写事件
- 测的是 **Runtime execution slot**，不是 GPU、KV 或供应商计费

真实流式 API 只做第 8.5 节的机制外推：事件顺序在真实 Runtime 上是否出现。那一批的等待差不进入 P95 主表。

### 2.3 失败样本留在分析里

超时、未完成、重规划失败、状态错误都保留。主分析是意向处理：预先分配的 trace 都进入分母。条件分析（例如“双臂都触发”）单独成表，不得替换主分析。右删失的等待记为观测窗长度，并单列 `censored_wait_count`。

### 2.4 操作检验（先于效应解释）

| 检验 | 预期 | 失败则 |
| --- | --- | --- |
| 有害、同一 seed：G1 与 G2 的撤销时刻和放槽时刻 | 差在数值误差内 | 政策实现把“任何信号”和“前提失败”做成了两套不同停读速度，RQ1 被污染 |
| 无害、同一 seed：G2 与 G0 都不产生 `false_cancel` | G2 的 `false_cancel=0`，且不产生 restart | RQ2 没有选择性 |
| 无害、G1 | 每个事件时仍在途的 false target 都有 restart | “误撤”没有变成额外负载，RQ2 无法解释 |
| 三政策 | `old_attempt_committed=0` 且重复副作用 = 0 | 安全门闩不一致，队列差不能归因于撤销时机 |
| 三政策 | 到达 JSON 哈希相同 | 配对失败，该 seed 作废 |

## 3. 三种工作流，外加误撤对象

每条到达有 `workflow_id`。每个焦点事件有 `event_id`。主实验每条 trace **一个**焦点事件。

| 角色 | 是谁 | 记录什么 | 是否主指标 |
| --- | --- | --- | --- |
| `target` | 前提被这次事件破坏的原工作流 | 撤销时刻、省下的剩余服务、最终是否有效提交 | 否。只解释机制 |
| `successor` | 同一工作流在失效后的必要后继 | 重规划服务量、再入队时刻、完成 | 否。它是成本 |
| `false_target` | 依赖同一来源但前提仍成立、却被 G1 停掉的工作流 | `false_cancel`、restart | 否。并入 RQ2，**不并入旁观者** |
| `bystander` | 不受该事件影响、不重规划、与上面几类争用同一组 slot 的独立工作流 | 等待、完成时间、完成率 | **是** |

判定：

1. 事件后 `premise_holds is False` 且该工作流依赖被改写的来源 → `target`；其后 attempt → `successor`。
2. 依赖同一来源但前提仍成立 → `false_target`；G1 产生的替代 attempt → `restart`。
3. 其余共享 slot 的工作流 → `bystander`。

主指标只在 `bystander` 上计算。把“排在后面的任务”统称后续任务，会把 successor 的变快算成旁观者收益。

## 4. 政策、调度与 \(\rho\)

### 4.1 三政策的实现合同

三组共用现有 Gateway：`linearize_revoke`、版本条件提交、`action_id` 去重。G0 可称为动作边界门闩，不称为 PlanFence 复现。

| 组 | 现有代码 | 槽 |
| --- | --- | --- |
| G0 | `signal_policy=premise`，`stop_on_cancel=False` | 读到原服务结束才释放 |
| G1 | `signal_policy=any_signal`，`stop_on_cancel=True` | 信号到达即释放 |
| G2 | `signal_policy=premise`，`stop_on_cancel=True` | 仅前提为假时释放 |

`max_inflight` 三组相同。确认性默认 **4** 个 slot。若 pilot 中 FCFS+G0 的旁观者中位等待低于 1 秒，先把到达加密或把 slot 改为 2，并在协议补丁里写下改动，再跑确认性。不得在看到效应方向之后改 slot。

另有一个机制格 **G2-delayed-release**：停读，但 slot 计数保持到原定服务终点。只在 FCFS、中负载、有害、\(\rho_h=0.5\) 上做。它用来区分“停止输出”和“把槽交给别人”。若不做，论文把 G2 写成组合处理。

### 4.2 调度器

三套都跑 G0/G1/G2。它们是基线，不是 EpochGate 的新算法。

| 策略 | 实现 | 论文称呼 |
| --- | --- | --- |
| FCFS | `FifoAdmissionScheduler(order="fifo", replan_to_tail=True)` | FCFS。successor 与 restart 入队尾 |
| SRPT | 新类 `SrptAdmissionScheduler` | clairvoyant oracle。剩余时间来自 trace 字段，禁止用事后真实长度回填 |
| Runtime-PLAS | 新类 `RuntimePlasScheduler` | Runtime-PLAS-inspired。优先级 = 该 `workflow_id` 已完成服务时间之和，相同则 FCFS |

等待超过 25 秒的工作流提到队首。不加 EDF、MLFQ、ATLAS。v1.8 的类别长度 SJF 留在历史 pilot，不与 SRPT 并列。调度器只决定谁占下一个槽，以及按政策发不发 `cancel`。不得 import gateway、environment、backend 实现。

### 4.3 重规划成本：一个定义，两条因果

用户给出的比值是控制变量：

\[
\rho=\frac{\text{后继服务时间}}{\text{目标原本剩余服务时间}}
\]

有害变化和无害变化里，“后继”的含义不同，所以确认性分成两个面板，禁止合成一个横轴。

| 面板 | 场景 | 对照 | 参数 | 分子与分母 |
| --- | --- | --- | --- | --- |
| A，对应 RQ1/RQ4 | 前提被破坏，successor 是必要工作 | G2 vs G0 | \(\rho_h\) | \(S_{\mathrm{successor}} / R_{\mathrm{obsolete}}\) |
| B，对应 RQ2/RQ4 | 前提仍成立，restart 是 G1 多出来的工作 | G2 vs G1 | \(\rho_b\) | \(S_{\mathrm{restart}} / R_{\mathrm{useful}}\) |

档位先用 \(0.5\)、\(1\)、\(2\)。回放器按档位写入服务量，并在日志里回读实际 `successor_service_s` 或 `restart_service_s`，确认执行值与预设值一致。\(\rho\) 不是从日志里事后拟合的。

无害信号比例 \(p_b\) 只做补充格（0.5）。主格是纯有害（\(p_b=0\)）或纯无害（\(p_b=1\)），避免两条机制混在一次 \(\Delta\) 里。

## 5. 指标

### 5.1 主指标

对 trace \(k\)、政策 \(g\)，只在该 trace 的旁观者集合上计算：

\[
W_{50}^{B},\; W_{95}^{B}
\]

\[
F_{95}^{B}=P_{95}(t_{\mathrm{finish}}-t_{\mathrm{arrival}})
\]

\(t_{\mathrm{start}}\) 是该旁观者首次 `slot_acquired`。未获得槽则等待记为窗长。\(t_{\mathrm{finish}}\) 是有效提交时刻。未完成不记成 0 等待。

预先指定的配对差：

| 效应 | 定义 | 服务的 RQ |
| --- | --- | --- |
| \(\Delta W^{\mathrm{early}}\) | \(W^{B}(\mathrm{G0})-W^{B}(\mathrm{G2})\) | RQ1 |
| \(\Delta W^{\mathrm{selective}}\) | \(W^{B}(\mathrm{G1})-W^{B}(\mathrm{G2})\) | RQ2 |
| \(\Delta F\) | 完成时间的同样差值 | RQ1、RQ2 |
| 调度交互 | 上述 \(\Delta\) 在三种调度器上的差 | RQ3 |
| \(\rho\) 交互 | 上述 \(\Delta\) 在 0.5、1、2 上的差 | RQ4 |

正值表示 G2 相对对应基线缩短了旁观者时间。\(\Delta W_{50}\) 与 \(\Delta W_{95}\) 都报。只改善中位数、不改善 P95，或只提早开始、不提早完成，必须写进结论。

P99 不进主结论。

### 5.2 机制指标（每条 trace 必有，用来解释主指标）

| 字段 | 解释什么 |
| --- | --- |
| `slot_reacquired_by` | 释放的槽给了 bystander、successor、restart、idle 还是 other |
| `reclaimed_slot_s` | 相对 G0 自然结束，提前放出的槽秒 |
| `successor_service_s` / `restart_service_s` | 实际执行的后继成本，核对 \(\rho\) |
| `false_restart_count` | RQ2 的负载注入 |
| `bystander_completion_rate` | 等待变好是否伴随完不成 |
| `effective_workflow_throughput` | 窗内有效完成的唯一工作流数 / 窗长 |
| `target_recovery_success` | 目标最终是否有效提交且旧 attempt 未提交 |
| `starvation_count` | 旁观者等待 > 25 秒，或被后到任务超越超过 2 次 |

目标词元差只放附录。

### 5.3 统计单位与区间

1. 独立单位是 **workload seed / trace**，不是其中上百个旁观者。
2. 先在 trace 内算出 \(W_{95}^{B}\) 等，再对 trace 间的配对差做 bootstrap：10000 次，种子写入协议，报 2.5% 与 97.5%。
3. 每条 trace 至少 **32** 个旁观者，否则该格的 P95 不进入主句。
4. 交互分析预先指定为：调度器三水平、\(\rho\) 三水平，报告每一格的配对差，不只报一个总平均。
5. 区间跨过 0，或效应低于第 6.3 节冻结的工程门槛，结论句用“未达到预先门槛”。不把区间写成显著性星号，也不做事后 Holm 挑格子。

### 5.4 什么叫有意义（先试点，再冻结，再确认）

工程门槛和统计功效在 **pilot 结束之后、确认性第一行之前** 写入 `v21_protocol.json`，之后不改。

候选规则（pilot 前的工作假设，不是已冻结门槛）：

- 旁观者 P95 等待的相对改善，候选工程门槛为基线 P95 的 **10%**
- 旁观者完成率下降超过 **2 个百分点**，候选为不可接受伤害
- 绝对秒数门槛取 pilot 里配对差标准差的量级，避免把噪声以下的 0.1% 写成贡献

冻结时同时写下：最小有意义效应、完成率伤害线、以及为达到 80% 功效所需的 trace 数。确认性每主格不少于 **50** 条独立 trace。若功效分析要求超过 200 条，缩小主格范围并写明放弃了哪一格，不在算力不够时把 20 条结果说成确认性。

统计上区间支持方向，但低于工程门槛：报告数字，不写入创新点主句。

## 6. 实验矩阵

先 pilot，再确认。所有数字在对应阶段结束前都不是论文结论。

### 6.1 共同工作负载

| 因素 | 主设定 |
| --- | --- |
| 到达 | open-loop，时刻写入 trace |
| 组成 | 40% 长 / 40% 短 / 20% 中。长度是服务秒 |
| 服务时间 | 短 2 s、中 6 s、长 16 s（pilot 可整体缩放，缩放因子冻结后再确认） |
| 焦点时机 | 主格为已服务 20%（早）。已服务 50% 为边界格 |
| 负载 | 中：FCFS+G0 旁观者中位等待 \(\ge 2\) s。高：\(\ge 5\) s。用到达间隔标定，不改政策 |
| slot | 4，按第 4.1 节的规则才允许改为 2 |
| 旁观者数 | 每 trace \(\ge 32\) |

### 6.2 E1 政策对照（RQ1、RQ2 的基础）

固定中负载、长短混合、早时机、FCFS、\(\rho=1\)。

- 有害：G0、G1、G2。G1 是操作检验。
- 无害：G0、G1、G2。G0 是操作检验。

## 7. 四种结果，以及各自允许的论文句子

实验设计正确时，下面四种都算完成。它们都还要满足操作检验、配对和复现，才算创新点被检验过。

| 结果 | 数据形态 | 可以写 | 不能写 |
| --- | --- | --- | --- |
| **A** | 有害上 G2 改善旁观者；无害上 G1 伤害旁观者；高 \(\rho\) 或某些调度器上收益变小 | 选择性撤销同时减少失效占用和无效 restart；收益有边界 | G2 在所有负载和调度器上更优 |
| **B** | 收益只在低 \(\rho\) 或 FCFS 上跨过门槛 | 何时值得提前撤销、何时调度器已经吸收了队头阻塞 | 撤销总是有系统收益 |
| **C** | G2 与 G0 的旁观者差低于门槛，但 `reclaimed_slot_s` > 0 | 提前撤销省了目标占用，没有变成旁观者收益；若接收者主要是 successor，写明槽被后继接回 | 旁观者外部性已被证明 |
| **D** | G1 或 G2 的旁观者 P95 变差，或完成率跌破伤害线 | 后继负载可以抵消甚至超过放出的槽；给出发生的 \(\rho\)、调度器和负载 | 把变差的格子从主表删掉 |

结果 C 或 D 本身不是创新。创新来自：对照公平、效应可重复、边界写得清。若操作检验失败，四种结果都不解释。

## 12. 2026-11-03 跑完之后的结论

协议哈希 `37f9846b2504b61c4e535940f9cc4df741fe9b462d6f99458b55a40ee2138213`。确认性 N=50。没有因为功效超过 200 而删格。操作检验通过，所以下面解释队列数字。

| 研究问题 | 这组数据允许的句子 |
| --- | --- |
| RQ1 | 有害、中负载、早时机、三种调度、\(\rho_h\in\{0.5,1,2\}\)，以及高负载 \(\rho_h=0.5\)，G2 相对 G0 的旁观者 P95 等待相对改善都超过 10%，区间下界大于 0。完成率差为 0 |
| RQ2 | 只在 \(\rho_b=2\) 上，G2 相对 G1 跨过 10% 等待门槛。\(\rho_b=1\) 的差是 0。\(\rho_b=0.5\) 上 G2 更差，区间整段为负 |
| RQ3 | 有害格子上三种调度的方向一致，幅度接近。无害格子上 FCFS 与 Runtime-PLAS 重合，SRPT 方向相同。调度没有把效应方向反过来 |
| RQ4 | 有害路径在 0.5、1、2 上方向不变。无害路径在 0.5 和 2 之间反转 |

对照第 7 节：有害主格接近结果 A 的前半句，而且不限于低 \(\rho\) 或 FCFS，所以不是结果 B。下一槽接收者在有害 G2 上全是 successor，但旁观者等待仍然下降，所以也不是结果 C。无害 \(\rho_b=0.5\) 是结果 D，主表保留。

可以支持的测量主张是：在这个有限 Runtime 槽的逻辑时钟回放里，前提失败后立即释放会缩短独立旁观者的 P95 等待；前提仍成立时，避免误撤只在 restart 长于剩余有效服务时改善旁观者等待，restart 更短时会使旁观者等得更久。

不能支持的是：GPU 或 KV 已回收、供应商已停止生成、G2 在所有格子上更优、v1.8 的后续等待就是旁观者 P95、完成率因此上升或下降。真实 API 的 60 条长任务只核对事件链：旧提交为 0，无害 G1 误撤 10/10，无害 G2 为 0/10。两个任务同时在飞，第二个任务不是排队旁观者，所以这次调用不替换上表的秒数。
