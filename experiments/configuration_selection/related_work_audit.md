# 配置选择实验的相关工作核对

本轮以仓库既有审查和已核对的最近来源界定先导问题。复核目标是避免把已知能力写成创新。投稿前仍需核对各工作最新版本和完整比较层级。

| 工作 | 已覆盖的内容 | 本轮主张边界 |
| --- | --- | --- |
| [SABench](https://arxiv.org/abs/2610.34167) | 终态和未授权副作用分别评判 | S0 → S1 为对照。主问题是 S1 → S2 的增量配置决策。 |
| [Stale Does Not Mean Unsafe](https://arxiv.org/html/2609.29522v1) | 固定提案、多种围栏、语义条件及拒绝后的重规划 | 围栏粒度和后继重试均有先例。 |
| [Cordon](https://arxiv.org/abs/2606.17573) 与 [效果历史异常](https://arxiv.org/abs/2609.15397) | 跨步骤语义约束、效果历史和工作流异常 | 效果历史、Claim 持久化和多步骤约束作为现有能力使用。 |
| [Evidence-Guided Recovery](https://arxiv.org/abs/2610.41453) | 任务义务、目标证据、终态证书与恢复评测 | 后继与证据判定已有先例。 |
| [From Version Conflicts to Decision Conflicts](https://arxiv.org/abs/2609.08015) | 区分普通版本变化与业务决策条件失效 | 本轮的良性版本变化和业务失效作为实验控制。 |
| [Revocation Is Not Complete at Receipt](https://arxiv.org/abs/2610.15991) | 交付、接收、执行和目标效果阶段分离 | 不将通知链本身写成创新。 |

先导观察到历史条件排除了原推荐，却没有发现主配置对照的决策增量。现阶段不据此声明建立了文献差异。
