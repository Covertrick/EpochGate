# 外部工作流资格审查

本轮先用只读源码与维护方文档审查 Flux Image Automation 和 create-pull-request，固定各自的 Git revision。最终状态只允许记录 PASS、FAIL 或证据不足，并保留每项依据。

外部工作流必须同时满足三个条件才进入动态复现。第一，首次推送结果可能不确定且真实客户端会启动恢复或重试。第二，记录它重送原动作，还是重新获取状态并产生新动作。第三，维护方文档、测试或真实工作流配置能支持「独立撤回之后，这次操作应当停止或保持撤回」的业务义务。活跃控制器对已声明期望状态的收敛，未经其他停止信号不能直接判为错误。普通快进推送同样纳入筛查。

只有三个条件都满足，才在隔离仓库用真实客户端运行 H1（原操作未落地）、H2（原操作落地后独立撤回）、H3（原操作落地未撤回）和反向提交负对照。测试从实际目标的引用、提交以及可读的操作证据评分。工作流资格未通过时保留本地先导结果，停止外部复现和托管宿主测试。
