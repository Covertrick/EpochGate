# 包发布撤回资格实验

先筛选 PyPI/Twine、crates.io/Cargo 和 npm。问题限于同一发布对象在第一次请求结果不确定后，自动重试是否会使明确撤回重新生效为公开发布。

动态试验使用固定 Twine 7.0.0 和隔离的回环 HTTP 服务。服务只实现从 Warehouse 源码核对的三个相关分支：新文件接受、完全相同的现存文件返回成功但不写入、删除后同名文件拒绝。Yank 只改变发布状态，保留文件。这是源规则的最小测试服务，不是 Warehouse 部署。

四种条件都令第一请求返回 HTTP 503。分别留存首次未接受、首次已接受、已接受后 yank、已接受后删除。第二次请求必须是同一文件内容，记录接收次数、目标写入次数、最终撤回状态和客户端退出。只使用合成 wheel 和虚构凭据。禁用客户端公网网络请求，实验服务绑定 127.0.0.1。

若重试使明确撤回失效，则进入服务端实装复核。若受测规则下撤回保持，则停止将同一发布的重试覆盖作为长文主张。客户端成功退出不能代替发布可用性指标。
