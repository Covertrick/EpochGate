# 恢复义务最小配对协议

冻结任务为历史履约 `ful-config-c4`。从归档核对实际发布字节及更新后合法字节。仓库任务定义的初始版本为 5、更新后为 6。归档模型字节带任务 ID 和版本 1，在更新前也不满足任务谓词。因此实验分开使用归档字节和按原任务定义冻结的初始合法字节。

## 矩阵

主矩阵固定初始合法载荷、授权、效果键、目标和故障窗口。交叉使用业务状态保持初始版本与升级到版本 6，以及目标尚未提交与目标已提交但调用方未保存回执。目标已提交的格子先在旧世界提交，再按计划更新世界。另追加归档原字节、目标尚未提交、世界已经变更的一组对照。该组用于复核历史现象，不能识别由版本变化造成的失效。

| 配置 | 恢复能用的记录与动作 |
| --- | --- |
| Claim 原有语义 | 使用现有 Claim 持久状态、目标查询和原字节续发路径 |
| Admission + 目标查询 | 可查同一效果键及目标摘要。没有持久意图时无法绑定原始提案。目标未发生时不续发。 |
| Admission + 持久意图 | 持久保存键与摘要，同样提供不可变暂存字节和目标查询。目标尚未发生时核对当前任务谓词后才续发。 |
| 诊断对照 | 固定 Claim 持久记录和恢复入口，仅在续发前启用相同的业务检查。识别差异是否来自持久机制或续发规则。 |

主矩阵四种条件各运行四种配置，归档额外条件运行同四种配置，共 20 格。每格子进程分别在耐久意图准备后、可选目标提交后以退出码 86 结束，父进程重开数据库，再实施世界变化并恢复。属于受控进程退出，未测掉电与并发写入。目标端使用相同 SQLite 接收器。保护过的暂存权限和目标读取能力为实验假设。

## 判定与停止条件

- 区分已发生的目标事实、能否匹配耐久意图、恢复是否新写、实际提交时业务有效性、目标最终是否满足当前业务目标。
- 已发生时仅对账。已提交的旧效果可以在提交时合法，世界变化后仍不能证明当前义务已经完成。
- 无目标记录时用可确认缺席的本地契约。旧字节失效时停止续发，不人为生成后继。未完成的当前义务单独记录。
- 若有条件的持久意图对照与改用同一条件的 Claim 对照得到相同目标与义务结果，则归因到证据与续发条件。原始 Claim 与无持久意图路径之间的差异不能单独支撑长文。只有强对照之后仍有可解释的额外差异，才考虑留出任务。夹具次数不作发生率。
